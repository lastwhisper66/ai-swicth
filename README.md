# AI Switch

带中文界面的本地桌面应用，用于集中管理 AI 供应商信息，并为本机和 WSL 中的 Claude Code、Codex 分别切换供应商配置。

已实现供应商增删改、多模型预设、Claude Code 与 Codex 独立切换、共通配置表单、完整配置预览、写前备份和恢复，并支持将供应商库与共通配置迁移到 AWS S3 兼容存储（包括 Cloudflare R2）。文件读写、云端加密与配置适配均在 Electron 主进程完成，界面只通过类型明确且经过运行时校验的 IPC 调用这些能力。

## 功能范围

- 使用自定义标题栏，左侧显示应用图标和 AI Switch，右侧提供最小化、最大化/还原及关闭按钮；空白区域支持拖动和系统默认的双击最大化/还原。窗口操作通过校验来源与参数的专用 IPC 调用主进程，关闭按钮沿用退出或系统托盘设置；加载中和读取失败时仍保留窗口按钮。
- 左侧固定导航按 Claude Code、Codex、Claude Code WSL、Codex WSL 排列，底部从上到下依次为刷新工具状态、当前主题、设置。主内容独立滚动，首页和设置中的供应商均按横向行展示，每行一个；窄窗口下行内信息与操作自动换行。设置分类在内容区顶部换行排列，避免重复侧栏挤占表单空间。每次点击侧栏“设置”默认进入第一个“应用设置”分类；添加、编辑供应商仍直接进入对应的供应商表单。
- 设置 → 关于集中展示应用介绍、名称、实际版本号、作者和 MIT 许可；版本号由 Electron 读取，不在标题栏重复展示。标题栏和关于页统一使用 `resources/icon.png` 中的实际应用图标，与打包图标资源保持一致，并保留原始颜色和透明边缘。
- 外观切换基于 shadcn/ui 官方 Vite 示例的 `ThemeProvider` 和 `useTheme`。左下角主题按钮展示当前模式，与刷新、设置按钮使用相同的无边框样式，每次点击按“跟随系统 → 明亮 → 黑暗 → 跟随系统”循环，不显示下拉菜单；显示器、太阳、月亮图标分别表示当前选择，悬停提示当前主题及下次切换目标。默认跟随系统，选择会在本地记住，并在启动时恢复。通过经过来源和参数校验的预加载接口，同步主进程的 `nativeTheme.themeSource`，让窗口和应用内容一起切换；跟随系统时实时响应系统外观变化。背景使用纯白或近黑色，不显示网格；通知、菜单和表单同步主题。导航、窗口按钮、信息卡片和版本标签复用现有 shadcn/ui 组件。
- 在设置页中按 Claude Code、Codex 两个工具管理供应商名称、API 地址、API Key 与模型。同一工具的本机和 WSL 入口共用供应商列表、模型、请求头和连接选项，已有本机供应商可直接应用到 WSL。
- 每个供应商可保存多个模型、指定默认模型；只填写实际写入工具配置的 API 模型 ID，不再维护独立显示名称。同一 ID 可保存不同选项的预设，下拉框仅在 ID 重复时追加选项说明，完全相同的预设追加序号。首页选择预设后应用，保存供应商不会立即写入工具配置；所选预设与实际生效模型匹配时显示绿色实心勾，尚未应用时显示空心勾。
- 供应商连接支持自定义请求头，编辑页使用普通文本输入框回填已保存的值，可直接编辑、保留或删除；配置预览中的请求头仍统一脱敏。Claude 支持四类模型路由，Codex 支持 Responses WebSocket 能力声明。
- Claude Code 模型填写 API 模型 ID，使用复选框启用 1M，自动添加或移除 `[1m]` 后缀；思考强度统一在共通配置设置，不提供 Fast 或自动压缩控件。Codex 的主思考强度也统一在共通配置设置；模型预设保留 1M、Fast、计划思考强度、思考摘要与回复详细程度。写入成功不代表网关支持，应用不调用付费 API 探测。
- 工具首页的“添加供应商”会进入设置页中对应工具的添加表单，无需勾选适用工具；保存与应用配置是两个独立操作。
- 添加和编辑使用页内表单，标签、输入框、说明与错误提示分别留出间距；Input、Input Group、Select 与默认 Button 统一沿用 shadcn/ui radix-nova 的 32px 默认高度及聚焦样式。
- 首页和设置中的下拉选项默认在输入框下方展开，与输入框留出间距，空间不足时自动避让窗口边缘。模型选项、默认模型路由和共通配置逐项独占一行；勾选项统一在左侧展示文字说明、右侧显示方形勾选框，关闭行为仍保持单选。
- 兼容此前同时用于两个工具的共用供应商，编辑时保留另一工具的模型并提示共用字段，不自动拆分历史记录。
- 分别识别 Claude Code 和 Codex 当前配置，未知配置显示为“外部配置”。
- 工具首页和配置路径页分别展示 CLI 安装状态与版本：已安装、未检测到安装、安装需检查。安装状态独立于配置状态，已有配置文件不代表 CLI 已安装。
- 设置 → 应用设置支持选择点击关闭按钮后“最小化到系统托盘”或“直接退出应用程序”，自动保存并在重启后保留；默认直接退出。托盘左键或双击恢复窗口，右键菜单仅含“退出应用程序”。
- 在工具首页直接点击供应商行的“应用”按钮（播放图标）切换配置，无需单独勾选；切换一个工具不会修改另一个工具。左侧 Base URL 下方直接放置“切换模型”下拉框；右侧依次为“应用”“编辑”和三点“更多”按钮，间距为 12px。设置列表保留“编辑”和“更多”；删除收进“更多”菜单，仍需二次确认。
- 首页与供应商设置使用统一的横向列表，当前使用的供应商以绿色标签标记。首页仅展示 Base URL 和模型，各占一行，长内容自动换行，不展示 API Key；设置列表和完整配置统一显示脱敏 Key。常规 Key 展示前 6 位和后 6 位，中间省略；较短 Key 减少显示位数，极短 Key 完全隐藏。API Key、云端 Secret Access Key 和备份密码复用基于 shadcn/ui Input Group 的密码组件：进入页面时载入真实内容，默认用密码圆点隐藏，可直接选中、编辑；眼睛按钮只切换当前内容的显示方式。载入密钥失败时提供重试入口，不用圆点占位符冒充输入值；普通快照不包含供应商 Key、请求头值或云端 Secret Access Key。只查看后保存继续保留原值，API Key 和 Secret Access Key 留空仍保留原值；Secret Access Key 通过单独的勾选项明确清除，备份密码清空则自动保存为空。
- 展示默认、环境变量或自定义配置目录，支持目录选择和移除自定义路径；旧版文件路径自动取父目录，之后固定管理该目录中的标准配置文件。
- 目录选择器从对应工具当前生效的配置目录打开；目录不存在时从最近存在的上级目录打开。配置路径页每个工具只展示一处目录和一处文件路径，可点击打开、使用“更换目录”，或展开“手动输入”编辑路径。
- 在设置的“共通配置”中，仅保留 Claude Code、Codex 两份共用模板，本机和 WSL 复用。每页上方为“快捷修改”，下方直接显示可编辑的 JSON/TOML 原文，不再切换表单与原文；思考强度、隐藏 AI 署名等选项与原文实时联动，未知字段保留。保存只更新 AI Switch 配置目录中的模板，应用供应商时才合并写入所选环境。
- 配置路径和当前文件预览集中在设置 → 配置路径；点击路径或“打开目录”进入配置目录，点击文件路径或“打开文件”通过系统默认程序打开 JSON/TOML 文件。文件不存在时提示先应用供应商，打开失败时提示检查权限或设置默认编辑器；不自动创建文件。
- 首页摘要展示当前供应商、实际模型 ID 和 Base URL；配置匹配时隐藏重复的成功说明，保留缺失、损坏、权限和外部修改等处理提示。设置 → 供应商设置 → 编辑供应商中的“完整配置”直接展开只读文本框，不提供预览模型选择或展开按钮。正在使用的供应商显示当前生效模型的草稿合并配置，其他供应商使用其默认模型；当前模型从草稿移除时回退到默认模型。内容随草稿更新，合并已保存的共通配置，查看不会写入工具文件；新增供应商保存后可进入编辑页查看。配置路径页直接展示当前文件内容；所有配置内容均在主进程脱敏 Key 及任意命名的 Header 值。Codex 的地址、模型和 API Key 均在 `config.toml` 中管理。
- 每次应用和恢复前创建本地备份，每个工具保留最近 20 份；恢复前状态也可再次找回。
- 对路径缺失、格式损坏、权限不足、外部并发修改及回滚失败提供中文反馈。
- 刷新、保存、应用和恢复等操作结果通过右下角 Toast 提示，不占用页面布局；关闭按钮位于 Toast 右上角，成功提示 4 秒后收起，错误和警告保留 8 秒，也可手动关闭。

## WSL 支持

Windows 上可在左侧进入 **Claude Code WSL** 和 **Codex WSL**。每个入口与对应的本机工具共用供应商和共通模板；工具配置目录、当前状态和接管记录按环境分别管理。供应商和共通配置只需保存一次，在本机或 WSL 点击“应用”时组合写入该环境；保存本身不修改工具配置。供应商设置和共通配置均仅保留 Claude Code、Codex 两个页签，供应商列表标注各环境的使用情况。

兼容旧版按四个入口保存的供应商和云端备份：本机记录直接共用，WSL 专属记录归入对应工具；同名冲突添加“迁移”编号。若同一条旧记录的本机与 WSL 配置不同，则将 WSL 配置保留为带“原 WSL”后缀的独立选择，保留模型、请求头和连接选项。读取仅在内存中转换，下次保存时升级供应商库，不修改真实工具配置。

默认通过 `wsl.exe` 读取默认发行版的名称和默认 Linux 用户的 HOME，分别管理 `~/.claude/settings.json` 和 `~/.codex/config.toml`。使用用户自己的交互式登录 shell，从 Linux HOME 启动，加载用户的 PATH 及导出的 `CLAUDE_CONFIG_DIR` / `CODEX_HOME`，配置目录要求为 Linux 绝对路径；不会套用 Windows 进程的配置环境变量。仅在某个已打开终端中临时设置、未持久化的环境变量无法自动发现，请手动选择对应目录。

WSL 执行层不识别或加载特定包管理器，也不扫描或补写 npm、nvm、Bun 的固定安装目录。npm 全局安装、官方原生安装、nvm、fnm、Volta、mise 等方式只要将可执行文件或 shim 加入用户 shell 的 PATH，就通过相同流程定位和执行。只在 shell 中定义的 alias / function 不作为安装依据；未加入 PATH 的自定义安装会提示将目录加入 shell 启动配置。启动配置异常或阻塞时会超时提示，不修改 shell 配置。常规 PATH 解析与 doctor 报告解析各自独立，后续新增工具无需新增包管理器适配。

设置 → 配置路径中的“更换目录”可选择 `\\wsl.localhost\发行版\home\用户名\.claude` 或 `.codex`；也接受 `\\wsl$\发行版\...`。可在目录选择器输入 `\\wsl.localhost` 浏览其他发行版。每个 WSL 入口可分别指定发行版和用户目录；CLI 检测使用所选发行版的默认 Linux 用户。移除自定义路径后回到默认发行版；更改默认发行版后点击“刷新工具状态”。WSL 入口拒绝 Windows 本机目录。

安装检测在相应发行版内运行 Linux 版 `claude doctor` / `codex doctor --json`，仅从报告读取安装信息和版本。shell 只负责加载用户环境和定位可执行文件，安装状态由 doctor 报告判断。Windows PATH 中的 CLI 不计为 WSL 安装；认证、网络或其他检查结果不参与安装状态判断，也不展示其警告。只要确认安装，统一显示绿色“已安装 · 版本号”，不把 doctor 的非零退出码直接当作未安装。首次读取会启动对应发行版；未安装 WSL、发行版启动失败或文件无法访问时显示中文原因和处理方法，本机入口仍可用。其他操作系统显示 WSL 不可用。

配置通过 Windows 的 WSL 文件共享路径读取，复用原有 JSON/TOML 适配、脱敏预览、写前备份、原子替换、读回校验与失败恢复。首次应用可创建缺少的 WSL 配置目录；预览和检测不会创建目录或文件。恢复按备份中的原发行版与原路径执行，不随当前路径设置重定向；恢复前也会创建安全备份。每个入口分别保留最近 20 份备份。应用或恢复后请在对应 WSL 发行版新建或重启工具会话。

人工验收时，在 WSL `/tmp` 下建立专用临时目录并用“更换目录”选中，使用占位 Key，依次检查两个 WSL 入口的新增、编辑、应用、切换模型、共通配置、预览和恢复，并核对其他三个入口的配置没有变化。检查目录缺失、JSON/TOML 损坏、无写入权限、发行版不可用和外部修改反馈；恢复原文件不存在的备份时，配置文件应删除。旧 v1/v2 云备份缺少 WSL 项时按空配置迁入，新 v3 备份包含四个入口。

2026-10-29：通过代码审查、类型检查、ESLint 和生产构建；在 FedoraLinux-44 中确认了发行版、Linux HOME 的只读发现及 `\\wsl.localhost` 目录访问。修正了通用 `sh -lc` 未加载用户 zsh 的 nvm 环境导致的漏检，并拆出与包管理器无关的 WSL 环境读取和命令执行层，移除特定安装目录补丁。人工确认同一用户 shell 可定位 nvm 安装的两个 CLI 及系统目录中的 uname。实际执行 doctor 确认 Windows Claude Code 2.1.312、Codex CLI 0.154.0，以及 WSL Claude Code 2.1.312、Codex CLI 0.165.0；两处 Codex 的安装检查均为正常，认证等诊断项失败不会当作未安装。其他安装方式、shell、完整界面操作、实际切换和恢复、多发行版及权限错误仍待人工验收。未修改真实工具配置，未添加测试代码或框架。

## 环境要求

- 推荐 Node.js 24 LTS，仓库中的 `.node-version` 固定主版本为 24。
- npm 11 或更高版本；本次使用 Node.js 24.18.0、npm 12.0.2。仅使用 npm 和 `package-lock.json`。
- 推荐 VS Code，安装仓库建议的 ESLint、Prettier 和 Tailwind CSS IntelliSense 扩展。

Tailwind CSS 使用 `@tailwindcss/vite`，只注册在 Electron Vite 的 renderer 配置中。当前 Tailwind CSS 4.3 支持 Vite 8，shadcn/ui 使用兼容 React 19 的 Radix 组件。

Claude Code 和 Codex 的品牌图标来自 [Lobe Icons](https://github.com/lobehub/lobe-icons/tree/7d7d0379f18b114a4009dc5cb85a7c375284f31b/packages/static-svg/icons)，分别使用 `claudecode-color.svg` 和 `codex.svg`，随应用本地打包，无需联网加载。原项目的 MIT 许可保留在 [图标许可](resources/lobe-icons-LICENSE.txt)，并随安装包分发。

## 安装与启动

```powershell
# 按锁文件安装依赖；首次安装会下载 Electron 并准备原生依赖。
npm ci

# 启动 Electron 桌面开发环境，渲染进程支持热更新。
npm run dev
```

安装、卸载、升级依赖和修改项目元数据必须使用 npm 命令，不直接编辑 `package.json` 或锁文件。首次安装需要网络；应用本身不会请求供应商 API，也不会验证 Key 或产生付费调用。

遇到网络问题时，可以在当前 PowerShell 会话中设置代理后重试：

```powershell
$env:HTTP_PROXY = 'http://127.0.0.1:7890'
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
$env:ALL_PROXY = 'http://127.0.0.1:7890'
```

`.npmrc` 保留脚手架的 Electron 下载镜像。npm 12 会提示这两个自定义镜像键为未知配置，该提示不影响已验证的安装与构建。

```text
│       ├── components/features/ # 工具配置页、供应商和设置页面
│       ├── assets/       # Tailwind 入口与主题变量
│       ├── components/ui/ # shadcn/ui CLI 生成的基础组件
│       └── lib/utils.ts  # cn 工具导出
└── shared/
    └── ipc.ts            # 主进程、预加载、界面共用的 IPC 契约
```

- `@renderer/*` 指向 `src/renderer/src/*`，供界面和 shadcn CLI 使用。
- `@shared/*` 指向 `src/shared/*`，已同时配置 Vite 和 TypeScript 的解析。
- `shared` 只放跨进程的类型、常量和纯逻辑，不能引入 Node.js 或 Electron 模块到界面。
- 文件读写、密钥处理和工具配置操作都放在主进程。界面只调用 `window.api`，不暴露通用 `ipcRenderer`、文件系统或进程环境变量。
- 启动升级迁移集中在 [`src/main/migrations/`](src/main/migrations/README.md)，于 Electron 就绪后、业务服务和窗口启动前依次执行；通过 SQLite `user_version` 记录进度，已完成步骤不会重复扫描旧文件。新增步骤静态注册，便于 Electron Vite 一起打包；业务操作中的归属字段移动仍由服务层处理。

## 进程边界与后续开发

窗口显式启用 `contextIsolation`、`sandbox`，关闭 `nodeIntegration`，阻止页面跳转和新窗口。预加载只暴露固定业务方法，不暴露通用 `ipcRenderer`、文件系统或环境变量。主进程校验请求来自应用窗口主框架、页面地址一致，并再次校验每个参数的实际运行时形状。应用使用单实例锁，主进程内所有写操作串行执行。

已保存的供应商 API Key 默认只通过列表摘要和完整配置回传脱敏标识，两处复用主进程的同一规则；其他令牌、密码和 Header 值在配置文本中完全隐藏。只有点击编辑器的眼睛按钮时，才通过校验来源和供应商 ID 的专用 IPC 按需读取完整密钥，在当前输入框中显示；默认快照、配置文本、日志和错误均不回传完整密钥。查看不修改供应商库，输入新值才替换；留空保留原值。供应商库和共通模板保存于本机 SQLite，历史备份正文保留为文件，均可能含明文敏感信息；云端迁移包单独使用备份密码加密。

打开配置位置也通过校验来源与参数的专用 IPC 完成：界面只传工具和“目录 / 配置文件”目标，主进程从已生效的路径设置解析实际位置、检查存在性，再调用系统默认打开方式；不会接受界面传来的任意文件路径。

仅在用户明确应用供应商或恢复工具备份时写入目标工具文件。写入流程为解析、生成、回读校验、本地备份、外部修改检测和原子替换；验证失败会恢复原内容。敏感配置文件以仅当前用户可读写的权限创建，并拒绝替换符号链接。Codex 只操作所选目录中的 `config.toml`，自定义目录优先于 `CODEX_HOME`。应用供应商时共通模板纳入同一组备份；单独保存或恢复共通模板只修改应用数据目录。

## 共通配置与预览

设置 → 共通配置按 Claude Code、Codex 管理两份模板；每份由本机与 WSL 共用。页面上方“快捷修改”和下方默认展示的 JSON/TOML 原文同步编辑同一份草稿；直接修改原文也会同步表单，格式无效时保留原文并暂停快捷修改和保存。Claude 的 `effortLevel` 与 Codex 的 `model_reasoning_effort` 作为顶层共通字段应用于全部模型。首次打开没有模板时显示空配置，读取和保存不要求安装工具或运行 WSL；可选的“从本机配置提取”才会读取本机工具文件，并排除供应商连接、模型、Header、路由和供应商模型选项。其他环境字段中的密钥仍可在原文中编辑，模板本身也应视为敏感配置。

点击“保存共通配置”只备份并更新 AI Switch 数据库中的共享模板，不选择应用环境、不改写任何工具文件。应用供应商时组合连接、所选预设和该工具共享模板；接管状态按环境记录上次应用的模板，后续应用可清除模板中已删除的字段，并保留模板之外的对象子字段与权限规则。没有模板时保留当前通用内容。模板备份的恢复也只改应用内模板，后续应用供应商时生效。

本机与 WSL 共用 SQLite 中按基础工具保存的一条模板记录，原文存为 TEXT，显式空模板不会重新启用旧内容。启动时校验并备份旧 JSON，兼容固定名称、原 `.common.v2.json` 和早期本机/WSL 原文，直接导入数据库，不合并多个模板；成功后旧文件退出活动存储。

旧模板中属于模型或连接的字段会列出归属冲突；选择一个明确的供应商和模型后，使用“迁移归属字段”处理，再保存共通配置。迁移仅更新所选记录和共享模板，不读取或应用工具文件，也不把当前 Header 复制到其他供应商。旧单模型供应商转换为具有稳定 ID 的默认预设，新增选项保持未设置，保存使用当前无版本字段的供应商格式。

Codex 模型选项的“工具默认”恢复接管前值；原本没有值时清除本应用写入的覆盖，已被外部修改的覆盖不强行还原。主思考强度不属于模型预设，切换模型不会改写顶层共通值。Claude 取消 1M 勾选只移除模型名末尾的 `[1m]`，不强制降低原生上下文容量；现有工具文件中的 Fast 和压缩配置按未管理字段保留。“隐藏 AI 署名”保存接管前的三个署名值，关闭后恢复它们并保留其他署名子字段；已有部分隐藏或自定义内容显示中间状态。

共通配置编辑期间，如果工具文件、目录、模板或接管状态被修改，保存会拒绝覆盖并提示重新读取。恢复历史备份时，还原那份备份记录的工具配置原路径、共通模板与接管状态；旧备份没有接管状态时会清除较新的状态。不会回退整个供应商库，也不会访问其他历史关联文件。

设置 → 配置路径直接展示当前文件内容，不会写入文件。“打开文件”通过系统默认程序查看磁盘原文。外部修改后点击顶部刷新，会核对连接、预设选项及 Header 的签名。JSON/TOML 按语义合并，保留无关字段；Codex 的切换、保存和预览会重新排版 TOML，注释及原始排版不会保留，写前备份保留原文。

## 配置兼容性

### 安装检测与路径展示

主进程在本机 `PATH` 与原生安装、npm、WinGet、Homebrew 等常见位置查找 `claude` / `codex`，运行带超时的 `claude doctor` / `codex doctor --json`，从报告确认安装并读取 CLI 版本。确认安装后统一显示绿色“已安装 · 版本号”，认证、配置、网络等其他检查结果不参与安装判断且不展示。启动文件存在但 doctor 不支持、无法运行、报告无法识别或权限受限时显示“安装需检查”，不会仅凭 `.claude` / `.codex` 目录判断安装成功。doctor 自身会检查认证、网络及更新等状态；应用不发送模型生成请求、不自动修复，仅向界面返回安装信息与版本，完整报告不会进入快照或日志。

Codex 统一显示 doctor 报告中的 CLI 引擎版本，优先使用 PATH 与常见独立安装位置中的 CLI。Windows 上找不到可识别 doctor 报告的独立 CLI 时，会从当前用户注册的 `OpenAI.Codex` 应用包定位桌面版内置的 `codex.exe`，运行同样的 doctor 命令并标注“桌面版内置”；不使用桌面应用包版本代替 CLI 版本。原生独立安装目录 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin` 也纳入查找，即使尚未加入当前进程的 PATH 仍可识别。

点击顶部刷新按钮会重新检测；常规保存操作复用短期缓存。本机入口检测运行 AI Switch 的操作系统中的 CLI，Windows 支持桌面版内置 CLI 回退；WSL 入口单独检测对应发行版中的 Linux CLI，不检测远程主机或其他平台的桌面应用；仅通过 shell 别名、函数或其他自定义位置暴露的命令可能无法识别。新安装后若桌面进程的 PATH 尚未更新，请重启 AI Switch。

未检测到工具且默认配置文件不存在时，配置路径页隐藏推测的默认路径，提示先安装后刷新，或手动指定已有配置目录。已存在的配置文件、环境变量路径和自定义目录仍可管理，状态会同时说明 CLI 是否可用；配置文件尚不存在时不能打开或预览。检测本身不会创建工具目录或配置。

### Claude Code

- 默认目录：`~/.claude`，管理其中的 `settings.json`；Windows 中 `~` 表示 `%USERPROFILE%`。
- 若设置 `CLAUDE_CONFIG_DIR`，使用该目录下的 `settings.json`。
- 应用字段：顶层 `model`，以及 `env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_AUTH_TOKEN`。
- 适用于暴露 Anthropic Messages 格式的代理或网关；不管理 Bedrock、Vertex 或 Foundry 专用字段。
- 思考强度仅提供 low、medium、high、xhigh，不按模型名禁用选项；只保存顶层 `effortLevel`，对全部模型生效，AI Switch 不管理 `modelSettings.<model>.effortLevel`。
- 1M 复选框适用于直接输入的模型名及网关别名：勾选在末尾添加一次 `[1m]`，取消则移除。实际容量、强度降级和网关支持由 Claude Code 与服务端决定；不提供 Fast 和自动压缩表单，原有字段保留。

### Codex

- 默认目录：`~/.codex`，管理其中的 `config.toml`。
- 若设置 `CODEX_HOME`，使用该目录下的 `config.toml`。
- 地址、模型和 API Key 统一写入 `config.toml`；状态识别、配置校验和预览也仅读取这个工具文件。
- 应用字段：顶层 `model`、`model_provider`，以及 AI Switch 自有的 `model_providers` 表，其中 `base_url` 保存地址，`experimental_bearer_token` 保存 API Key。
- 自有 provider 显式设置 `requires_openai_auth = false`，使用该表中的直接令牌；不会生成 `env_key` 或命令认证配置。
- 自有 provider 固定使用 `wire_api = "responses"`，适用于 OpenAI Responses 兼容端点。
- 使用 `smol-toml` 校验并合并完整 TOML，保留未知字段并重新排版。若格式损坏或目标字段无法安全识别，会拒绝写入。
- 主思考强度只保存为顶层 `model_reasoning_effort`，对全部模型生效；实际支持级别由当前模型和网关决定。1M 固定写入 `1000000`，Fast 同步 `service_tier` 与 `features.fast_mode`；不附带压缩阈值。计划模式思考强度仍按模型预设保存，并按官方型号显示支持的级别。

在 Codex 页面重新应用已保存的供应商，会把供应商库中保存的 Key 连同地址、模型一起写入 TOML。应用不会自动访问、删除或修改 Codex 的其他认证文件；如果恢复的 TOML 未保存 Key，操作结果会提示重新应用已保存的供应商。

两个工具都可能在新会话启动时读取模型或凭据，因此应用或恢复后界面会提示新建或重启对应会话。更高优先级的命令行参数、项目配置、托管策略或进程环境变量仍可能覆盖用户配置文件。

## 文件位置、格式与云端迁移

应用数据根目录使用 Electron 的 `app.getPath('userData')`。Windows 通常是 `%APPDATA%\ai-switch`，macOS 通常是 `~/Library/Application Support/ai-switch`，Linux 通常是 `~/.config/ai-switch`；开发调试时可用 `AI_SWITCH_USER_DATA_DIR` 覆盖。

- `ai-switch.db`：供应商、工具连接、模型预设、Header、两份通用模板、主题及关闭偏好、S3 设置与密码、工具路径、接管状态、备份索引和待恢复操作。
- `ai-switch.db-wal`、`ai-switch.db-shm`：SQLite 管理的辅助文件，不能将单独复制主数据库当作完整备份。
- `backups/<tool-id>/<uuid>.backup`：工具文件和模板的本地操作备份正文，每个工具保留最近 20 份，索引进入数据库。
- `backups/configurations/<uuid>.json`：覆盖前的供应商和模板快照，以及旧 JSON 导入前的原文备份；普通快照可从备份页面恢复，迁移原文在目录中保留。
- `backups/database/<时间戳>-<uuid>.db`：已有数据库升级前，通过 SQLite 在线备份接口创建的完整恢复副本。

数据库迁移使用全局 `PRAGMA user_version`，不在业务记录或活动文件名中添加版本号。旧 `providers.json`、`settings.json`、`preferences.json`、模板、接管 JSON、备份索引及旧完成清单经过校验和原文备份后导入；导入和版本更新在同一个事务内完成，失败保留源文件，成功后清理旧活动文件。清理被占用或发现外部修改时保留并提示，后续只用数据库，不重复导入。详细边界见 [SQLite 存储说明](src/main/database/README.md) 和 [迁移维护说明](src/main/migrations/README.md)。

数据库及备份正文均可能含本机明文敏感信息。主题偏好从旧浏览器存储一次性导入，只保存“跟随系统 / 浅色 / 深色”的选择；系统实际颜色实时计算。大型文档、图片、附件、日志及 Electron 缓存继续使用文件。

Claude Code 实际工具文件是所选目录下的 `settings.json`，Codex 是 `config.toml`；供应商仅在用户点击“应用”时写入对应工具，密钥按工具协议写为明文。

云端绑定只保存连接信息，不自动上传或恢复。两个操作均使用整份覆盖：

- **保存到云端**：用本地完整供应商和两份通用模板替换 `<prefix>/backup.json.enc`，包含全部 API Key/Header；不读取旧存档、不比较修改时间、不合并内容，服务端最后成功提交者生效。
- **应用云端版本**：选择当前或历史存档，下载、解密并完整校验后创建本机快照，再在一个 SQLite 事务中登记快照索引并覆盖供应商和模板；本地新增、编辑、删除和 Key 修改全部以存档为准，空模板和空列表同样覆盖，写入失败整组回滚。

云端从数据库一致快照中导出供应商和通用模板，不上传整个数据库；主题、设备路径、字段接管状态、连接设置、本机密码和本地历史备份均不上传或覆盖。恢复不修改 Claude Code/Codex 的真实文件，完成后自行选择供应商应用；应用历史存档不自动回传云端。

备份文件使用 scrypt 派生密钥和 AES-256-GCM 整体加密，API Key 始终随文件备份，不另设字段加密或排除选项。新文件和正文不带格式版本标记，兼容读取旧 `.v1/.v2/.v3.json.enc` 加密存档；旧存档中的接管状态不导入，旧独立模板选择本机项（包括显式空值），仅缺少本机项时使用 WSL 项，不合并任何本地内容。

保存成功后写入 `<prefix>/backups/<UTC 时间戳>-<UUID>.json.enc` 供历史选择，按设置保留最近 1、3、5、10 或 20 份（默认 5）；固定当前对象另存，同一快照在列表中只展示一次。历史保存或清理失败提示当前存档已成功保存。上传响应丢失时通过本次存档标识查询确认，无法确认时提示结果待确认，不误报成功。分页列出旧、新命名的历史对象后清理，其他对象不受影响。

S3 凭据需要当前前缀的列出、读取、写入和删除权限；连接测试只检查访问及列表，不写入对象。存储桶自身的历史版本由其生命周期规则管理。

备份密码按现有约定保存在本机数据库的云端设置中，输入完成后自动保存，重启回填，清空可移除；密码不进入云端文件、对象元数据或日志，换设备恢复需提供对应密码。密码错误、格式损坏或下载失败不修改本地供应商和模板。
