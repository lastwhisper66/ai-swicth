# AI Switch

带中文界面的本地桌面应用，用于集中管理 AI 供应商信息，为本机和 WSL 中的 Claude Code、Codex 分别切换供应商配置，并管理 VS Code Copilot 的 BYOK 模型。

已实现供应商增删改、多模型预设、Claude Code 与 Codex 独立切换、共通配置表单、完整配置预览、写前备份和恢复，并支持将供应商库与共通配置迁移到 AWS S3 兼容存储（包括 Cloudflare R2）。文件读写、云端加密与配置适配均在 Electron 主进程完成，界面只通过类型明确且经过运行时校验的 IPC 调用这些能力。

Codex 和 Codex WSL 首页提供“清理未管理供应商”，点击后先弹出清理预览，列出当前环境所选 `config.toml` 的完整路径、待删除供应商的名称、`model_providers` 表路径及脱敏后的 TOML 内容，点击“确认清理”后执行。保留与应用内 Codex 供应商 ID 对应的表，清除其余未被引用的表（包括手动添加的供应商）；当前 `model_provider`、旧版内嵌 Profile 以及同目录新版 `*.config.toml` Profile 文件仍引用的表会保留并提示先切换。Profile 文件只读取，不改写。清理前自动备份原文与接管状态，可在设置 → 备份与恢复中恢复“清理前”备份；没有可清理内容时不改写文件、不创建备份。配置损坏、Profile 无法读取或预览后配置、供应商、Profile 发生变化时停止操作，需修复或重新预览后确认。清理沿用现有 TOML 序列化方式，会重新排版，原注释保留在备份中。

## 功能范围

- 左侧为贯穿窗口高度的侧边栏，顶部以大标题显示应用图标和 AI Switch，与下方工具入口区分；品牌行右侧按钮可收起为图标栏，展开按钮位于收起后的应用图标下方，悬停或聚焦图标可查看名称，收起状态保存在本机。右侧自定义标题栏保留主题、最小化、最大化/还原及关闭按钮；标题栏与品牌区空白处支持拖动和系统默认的双击最大化/还原，收起按钮不参与拖动。窗口操作通过校验来源与参数的专用 IPC 调用主进程，关闭按钮沿用退出或系统托盘设置；加载中和读取失败时仍保留窗口按钮。
- 默认窗口为 1600×1080，在主显示器可用工作区居中；工作区较小时自动缩小到可用尺寸，最小窗口限制也不超过工作区。AI 应用、工具首页及设置各分类共用占满可用宽度的内容区，放大窗口时同步扩展。AI 应用表格的额外宽度分配给应用名称和路径，shell、版本与操作列保持紧凑；小窗口仅表格内部横向滚动。
- 左侧默认按 Claude Code、Codex、Claude Code WSL、Codex WSL 排列，「AI 工具」分组中的入口可直接拖动排序，不显示额外拖动按钮，键盘可按 Alt + 上下方向键调整位置，与“AI 应用”管理表格共用顺序；隐藏入口不丢失顺序，再次显示时恢复原有相对位置。底部提供“AI 应用”和“设置”；主题切换位于标题栏，全局重新检测统一放在 AI 应用页。AI 应用页可分别隐藏工具入口，管理入口始终保留；启动时默认入口已隐藏则进入 AI 应用页。主内容独立滚动，首页供应商按横向行展示，每行一个，左侧手柄支持拖动或键盘排序，本机 / WSL 同步；顺序写入本机 SQLite，编辑供应商不会重新排列，新供应商追加末尾，保存失败恢复原顺序。窄窗口下行内信息与操作自动换行。设置分类在内容区顶部换行排列，避免重复侧栏挤占表单空间。每次点击侧栏“设置”默认进入第一个“应用设置”分类；添加、编辑供应商在当前工具横幅下方打开对应表单。
- 启动立即展示标题栏、侧栏及首页框架；本地供应商、设置与备份通过独立的启动接口读取，不等待 CLI 或 WSL 检测。四个工具的状态分别异步加载并立即呈现，未完成的安装状态使用加载占位；失败只在对应工具显示原因与重试。供应商列表读取后即可新增、编辑和删除，“应用”需等待对应工具状态确认，较慢的 WSL 不阻止其他入口和设置使用。
- 设置 → 关于集中展示应用介绍、名称、实际版本号、作者和 MIT 许可；版本号由 Electron 读取。侧边栏和关于页统一使用 `resources/icon.png` 中的实际应用图标，与打包图标资源保持一致，并保留原始颜色和透明边缘。
- 外观切换基于 shadcn/ui 官方 Vite 示例的 `ThemeProvider` 和 `useTheme`。左下角主题按钮展示当前模式，与刷新、设置按钮使用相同的无边框样式，每次点击按“跟随系统 → 明亮 → 黑暗 → 跟随系统”循环，不显示下拉菜单；显示器、太阳、月亮图标分别表示当前选择，悬停提示当前主题及下次切换目标。默认跟随系统，选择会在本地记住，并在启动时恢复。通过经过来源和参数校验的预加载接口，同步主进程的 `nativeTheme.themeSource`，让窗口和应用内容一起切换；跟随系统时实时响应系统外观变化。背景使用纯白或近黑色，不显示网格；通知、菜单和表单同步主题。导航、窗口按钮、信息卡片和版本标签复用现有 shadcn/ui 组件。
- 各工具首页横幅右侧统一提供“添加供应商”“功能配置”，使用 44px 高度、图标和清晰的边框与底色；子页另有“返回首页”，所有页面只处理当前工具，不再使用全局供应商工具选择器。首页直接提供编辑、删除和排序，并显示脱敏 API Key 和各环境使用状态，不再重复设置管理供应商页。功能配置分为“功能选项”和“配置路径”，两个入口使用带图标和边框的按钮式标签，选中项以高对比底色突出。Claude Code 和 Codex 的本机与 WSL 共用供应商和共通模板，配置路径按环境隔离；Copilot 使用独立的原生配置表单与存储。全局设置仅保留应用设置、备份与恢复、关于。
- 每个供应商可保存多个模型、指定默认模型；只填写实际写入工具配置的 API 模型 ID，不再维护独立显示名称。同一 ID 可保存不同选项的预设，下拉框仅在 ID 重复时追加选项说明，完全相同的预设追加序号。首页选择预设后应用，保存供应商不会立即写入工具配置；所选预设与实际生效模型匹配时显示绿色实心勾，尚未应用时显示空心勾。
- 供应商连接支持自定义请求头，新增或编辑无请求头的供应商时默认显示一行名称和值，完全留空的行不会保存或进入预览。编辑页使用普通文本输入框回填已保存的值，可直接编辑、保留或删除；配置预览中的请求头仍统一脱敏。Claude 支持四类模型路由，Codex 不再提供 Responses WebSocket 能力声明。
- Claude Code 模型填写 API 模型 ID，使用 Switch 启用 1M，自动添加或移除 `[1m]` 后缀；思考强度统一在共通配置设置，不提供 Fast 或自动压缩控件。Codex 的主思考强度、1M 与 Fast 均归共通配置，供应商表单只管理模型 ID。共通配置原文标题旁可展开“快捷设置”，1M 旁展示固定的 `model_context_window = 1000000` 与可编辑的 `model_auto_compact_token_limit`，阈值默认 900,000（900k）tokens，关闭 1M 时置灰。快捷操作立即更新下方 TOML 草稿，所有供应商和模型共用。写入成功不代表网关支持，应用不调用付费 API 探测。
- 工具首页的“添加供应商”在当前工具页面打开添加表单，保存或取消返回来源列表，无需选择适用工具；保存与应用配置是两个独立操作。
- 添加和编辑使用页内表单，标签、输入框、说明与错误提示分别留出间距；Input、Input Group、Select 与默认 Button 统一沿用 shadcn/ui radix-nova 的 32px 默认高度及聚焦样式。
- 首页和设置中的下拉选项默认在输入框下方展开，与输入框留出间距，空间不足时自动避让窗口边缘。Claude 供应商的 1M 和 Codex 共通配置快捷设置中的开关项使用左侧 Switch；Codex 1M 右侧展示上下文窗口与压缩阈值，小窗口自动换行。确认类勾选项继续使用复选框，关闭行为仍保持单选。
- 兼容此前同时用于两个工具的共用供应商，编辑时保留另一工具的模型并提示共用字段，不自动拆分历史记录。
- 分别识别 Claude Code 和 Codex 当前配置，未知配置显示为“外部配置”。
- 工具首页和配置路径页分别展示 CLI 安装状态与版本：已安装、未检测到安装、安装需检查。安装状态独立于配置状态，已有配置文件不代表 CLI 已安装。
- 设置 → 应用设置支持选择点击关闭按钮后“最小化到系统托盘”或“直接退出应用程序”，自动保存并在重启后保留；默认直接退出。托盘左键或双击恢复窗口，右键菜单仅含“退出应用程序”。
- 在工具首页直接点击供应商行的“应用”按钮（播放图标）切换配置，无需单独勾选；切换一个工具不会修改另一个工具。左侧 Base URL 下方直接放置“切换模型”下拉框；右侧依次为“应用”“编辑”和三点“更多”按钮，间距为 12px。管理列表保留“编辑”和“更多”；删除收进“更多”菜单，仍需二次确认。
- 首页与供应商管理使用统一的横向列表，当前使用的供应商以绿色标签标记。首页仅展示 Base URL 和模型，各占一行，长内容自动换行，不展示 API Key；管理列表和完整配置统一显示脱敏 Key。常规 Key 展示前 6 位和后 6 位，中间省略；较短 Key 减少显示位数，极短 Key 完全隐藏。API Key、云端 Secret Access Key 和备份密码复用基于 shadcn/ui Input Group 的密码组件：进入页面时载入真实内容，默认用密码圆点隐藏，可直接选中、编辑；眼睛按钮只切换当前内容的显示方式。载入密钥失败时提供重试入口，不用圆点占位符冒充输入值；普通快照不包含供应商 Key、请求头值或云端 Secret Access Key。只查看后保存继续保留原值，API Key 和 Secret Access Key 留空仍保留原值；Secret Access Key 通过单独的勾选项明确清除，备份密码清空则自动保存为空。
- 展示默认、环境变量或自定义配置目录，支持目录选择和移除自定义路径；旧版文件路径自动取父目录，之后固定管理该目录中的标准配置文件。
- 目录选择器从对应工具当前生效的配置目录打开；目录不存在时从最近存在的上级目录打开。配置路径页展示可点击的路径，通过“更换目录”选择位置，不展示路径输入框或当前文件内容文本框。
- 在各工具的“功能配置 → 功能选项”中，分别管理 Claude Code、Codex 的共用模板，本机和 WSL 复用。每页直接显示可编辑的 JSON/TOML 原文，原文标题旁提供可展开的“快捷设置”：Claude Code 支持思考强度与隐藏 AI 签名（commit、PR 和 session URL），Codex 支持 1M、压缩阈值与 Fast，控件与原文双向同步。标题、快捷设置、从本机提取与保存按钮支持换行，保存按钮在内容未修改时仍可使用；未知字段保留。保存只更新 AI Switch 数据库中的模板，应用供应商时才合并写入所选环境。
- 配置路径位于各工具的“功能配置 → 配置路径”；点击目录路径或“打开目录”进入文件浏览器，点击文件路径或“打开文件”通过系统默认程序打开 JSON/TOML 文件。文件不存在时提示先应用或同步供应商，打开失败时提示检查权限或设置默认编辑器；打开操作不自动创建文件。
- 首页顶部卡片仅展示工具安装版本和配置状态，不重复展示供应商、模型和 Base URL；这些连接信息在下方供应商行查看。配置匹配时隐藏重复的成功说明，保留缺失、损坏、权限和外部修改等处理提示。工具首页 → 编辑供应商中可展开“完整配置预览”，查看只读文本，不提供预览模型选择。正在使用的供应商显示当前生效模型的草稿合并配置，其他供应商使用其默认模型；当前模型从草稿移除时回退到默认模型。内容随草稿更新，合并已保存的共通配置，查看不会写入工具文件；新增供应商保存后可进入编辑页查看。配置预览在主进程脱敏 Key 及任意命名的 Header 值。Codex 的地址、模型和 API Key 均在 `config.toml` 中管理。
- 每次应用和恢复前创建本地备份，每个工具保留最近 20 份；恢复前状态也可再次找回。
- 对路径缺失、格式损坏、权限不足、外部并发修改及回滚失败提供中文反馈。
- 刷新、保存、应用和恢复等操作结果通过下方居中的 Toast 提示，不占用页面布局；新通知从底部出现，已有通知向上移动，最多同时显示 3 条，超出时淘汰最早的通知。鼠标悬停时暂停自动关闭，移开后继续剩余倒计时；点击通知正文或右上角关闭按钮可关闭，也支持聚焦通知后按 Enter 或空格。常规提示 4 秒后收起，业务操作错误和警告保留 8 秒。

## 会话管理

侧边栏底部的“会话”入口集中浏览 Claude Code、Codex 和 **Copilot CLI** 已有的本地会话。顶部直接切换工具，Claude Code 和 Codex 另有本机 / WSL 环境选择；会话目录可独立更换、恢复默认，不会修改供应商配置目录。

- 默认按项目分组，也可按更新时间排序；支持项目筛选、最近 24 小时 / 7 天 / 30 天筛选和列表分页。
- 搜索范围可选标题、消息内容、会话 ID 或全部。消息全文由主进程按需读取，不上传、调用模型或创建会话；首次全文搜索大量历史可能较慢，改变条件后停止旧检索。单个日志超过 128 MiB 或 250,000 个事件时提示使用原工具查看，并明确提示未完整检索。
- 点击会话在右侧以只读对话展示提问和回答，支持 Markdown、代码块、表格、消息复制和分页加载；工具调用、执行结果、系统记录默认折叠。图片显示附件占位，不读取外部图片；不执行记录中的 HTML 或链接。
- 支持单个、跨列表分页选择和批量删除，每次主动选择上限 500 个。删除预览列出完整会话及已发现的 Codex 派生子会话；确认后永久移除，不提供消息级删除、回收站或 Markdown 导出，不自动创建会话备份。预览过期、会话变化或新增派生会话时要求重新确认。批量操作分别报告成功、失败和关联记录未清理的情况。
- Claude 删除会话正文、对应子代理 / 工具结果目录及会话专用附件、文件历史等，清理旧项目索引和输入历史中匹配的会话记录；保留项目代码、项目记忆及工具配置。Codex、Copilot CLI 使用原工具的删除接口，避免直接修改其 SQLite 数据库。Codex 删除接口会级联删除派生子会话，预览包含关联范围；Copilot CLI 仅处理本地会话，远端副本由原工具或 GitHub 管理。
- 删除前检查文件是否变化、最近是否仍在写入，以及可用的运行标记 / 工具状态。其他进程可能继续写入，因此删除前应关闭原工具中打开的目标会话。操作期间不允许退出应用。

默认数据位置与兼容方式：

| 工具            | 默认数据根目录                          | 读取与删除                                                                                                                           |
| --------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Claude Code     | `CLAUDE_CONFIG_DIR` 或 `~/.claude`      | 读取 `projects/<project>/<session-id>.jsonl`；仅删除目标会话及关联数据。JSONL 是内部格式，后续版本可能需要更新适配。                 |
| Codex           | `CODEX_HOME` 或 `~/.codex`              | 读取 `sessions/`、`archived_sessions/` 日志并合并 `codex app-server` 列表；支持无日志文件的原生历史。通过 `thread/delete` 删除。     |
| Copilot CLI     | `COPILOT_HOME` 或 `~/.copilot`          | 读取 `session-state/<id>/events.jsonl` 并合并原生会话列表，通过 `session.delete` 删除。                                              |
| VS Code Copilot | `%APPDATA%/Code/User`（或平台等价目录） | 读取 `workspaceStorage/*/chatSessions/<id>.json` / `<id>.jsonl` 及无项目窗口会话，标题来自 `state.vscdb`；按会话删除正文并清理索引。 |

Claude / Codex 会话只检查默认数据根目录及工具已经配置的数据根目录，重复路径会去重；WSL 也遵循这两个检查点。Copilot CLI 同样合并默认目录与 `COPILOT_HOME`。VS Code Copilot 只检查默认 User 数据根目录及应用已保存的 VS Code 配置所在根目录。Codex 和 Copilot CLI 未安装、版本不支持会话接口或接口不可用时，仍可浏览可识别的本地日志，但禁止删除。VS Code 删除前要求退出所有 VS Code 窗口，避免编辑器缓存重新写回。

实现位于 [`src/main/sessions/`](src/main/sessions/README.md)、[`src/shared/sessions.ts`](src/shared/sessions.ts) 和界面的 `SessionsPage` / `SessionConversation`。读取、检索、路径检查、删除计划与 CLI 通信都在主进程，IPC 只接受校验后的查询、会话键及短期确认令牌，不接受任意文件删除路径。内容仅暂存在有数量和容量限制的内存缓存，不复制进应用数据库或云端备份。

所有应用统一放在同一张表格中，不按已安装和未安装分区。每行最左侧的六点手柄通过新版 `@dnd-kit/react` 支持拖动排序：整行浮起并跟随鼠标上下移动，其他行平滑让位，虚线占位框和“松开放到第几位”提示明确落点，松开时动画归位。移动超过 5px 才开始拖动；拖动中可按 Esc 取消，列表超出窗口时支持边缘自动滚动。键盘可按空格或回车提起、上下键移动、空格或回车放下，也保留 Alt + 上下方向键直接调整；开启系统减少动态效果时关闭位移动画。顺序仅在放下后保存在本机 SQLite，刷新或重启后保留，保存失败恢复原顺序；侧边栏按同一顺序显示可见的供应商工具入口，两处调整即时同步，隐藏入口保留其顺序。旧设置没有顺序时使用工具目录默认顺序，新增工具追加到已保存列表末尾，已移除的目录项自动略过。

拖动实现遵循官方 [React 快速入门](https://dndkit.com/react/quickstart)及[迁移指南](https://dndkit.com/react/guides/migration)，使用 `DragDropProvider`、`@dnd-kit/react/sortable` 的 `useSortable` 和 `DragOverlay`。`@dnd-kit/dom` 用于输入、反馈和中文无障碍配置，`@dnd-kit/abstract` 用于纵向限制；这些属于新版架构，未使用 Legacy 包。

## WSL 支持

Windows 上可在左侧进入 **Claude Code WSL** 和 **Codex WSL**。每个入口与对应的本机工具共用供应商和共通模板；工具配置目录、当前状态和接管记录按环境分别管理。供应商和共通配置只需保存一次，在本机或 WSL 点击“应用”时组合写入该环境；保存本身不修改工具配置。供应商管理直接在对应工具首页操作，功能配置也位于对应工具页面，列表标注各环境的使用情况；本机与 WSL 仍共用对应工具的模板。

兼容旧版按四个入口保存的供应商和云端备份：本机记录直接共用，WSL 专属记录归入对应工具；同名冲突添加“迁移”编号。若同一条旧记录的本机与 WSL 配置不同，则将 WSL 配置保留为带“原 WSL”后缀的独立选择，保留模型、请求头和连接选项。读取仅在内存中转换，下次保存时升级供应商库，不修改真实工具配置。

默认通过 `wsl.exe` 读取默认发行版的名称和默认 Linux 用户的 HOME，分别管理 `~/.claude/settings.json` 和 `~/.codex/config.toml`。按照 AI 应用页的 shell 设置，从 Linux HOME 启动，加载用户的 PATH 及导出的 `CLAUDE_CONFIG_DIR` / `CODEX_HOME`，默认使用自动 shell，启动参数统一为 `-lic`；配置目录要求为 Linux 绝对路径，不会套用 Windows 进程的配置环境变量。仅在某个已打开终端中临时设置、未持久化的环境变量无法自动发现，请手动选择对应目录。

WSL 执行层不识别或加载特定包管理器，也不扫描或补写 npm、nvm、Bun 的固定安装目录。npm 全局安装、官方原生安装、nvm、fnm、Volta、mise 等方式只要将可执行文件或 shim 加入用户 shell 的 PATH，就通过相同流程定位和执行。只在 shell 中定义的 alias / function 不作为安装依据；未加入 PATH 的自定义安装会提示将目录加入 shell 启动配置。启动配置异常或阻塞时会超时提示，不修改 shell 配置。常规 PATH 解析与 doctor 报告解析各自独立，后续新增工具无需新增包管理器适配。

工具页面 → 功能配置 → 配置路径中的“更换目录”可选择 `\\wsl.localhost\发行版\home\用户名\.claude` 或 `.codex`；也接受 `\\wsl$\发行版\...`。可在目录选择器输入 `\\wsl.localhost` 浏览其他发行版。每个 WSL 入口可分别指定发行版和用户目录；CLI 检测使用所选发行版的默认 Linux 用户。移除自定义路径后回到默认发行版；更改默认发行版后在 AI 应用页点击“重新检测”。WSL 入口拒绝 Windows 本机目录。

安装检测在相应发行版内运行 Linux 版 `claude --version` / `codex --version`，仅从版本输出确认安装。shell 负责加载用户环境和定位可执行文件；Windows PATH 中的 CLI 不计为 WSL 安装。认证、网络或其他健康检查不参与安装状态判断。确认安装后统一显示绿色“已安装 · 版本号”。首次读取会启动对应发行版；未安装 WSL、发行版启动失败或文件无法访问时显示中文原因和处理方法，本机入口仍可用。其他操作系统显示 WSL 不可用。

配置通过 Windows 的 WSL 文件共享路径读取，复用原有 JSON/TOML 适配、脱敏预览、写前备份、原子替换、读回校验与失败恢复。首次应用可创建缺少的 WSL 配置目录；预览和检测不会创建目录或文件。恢复按备份中的原发行版与原路径执行，不随当前路径设置重定向；恢复前也会创建安全备份。每个入口分别保留最近 20 份备份。应用或恢复后请在对应 WSL 发行版新建或重启工具会话。

## 进程边界与后续开发

窗口显式启用 `contextIsolation`、`sandbox`，关闭 `nodeIntegration`，阻止页面跳转和新窗口。预加载只暴露固定业务方法，不暴露通用 `ipcRenderer`、文件系统或环境变量。主进程校验请求来自应用窗口主框架、页面地址一致，并再次校验每个参数的实际运行时形状。应用使用单实例锁，主进程内所有写操作串行执行。

已保存的供应商 API Key 默认只通过列表摘要和完整配置回传脱敏标识，两处复用主进程的同一规则；其他令牌、密码和 Header 值在配置文本中完全隐藏。只有点击编辑器的眼睛按钮时，才通过校验来源和供应商 ID 的专用 IPC 按需读取完整密钥，在当前输入框中显示；默认快照、配置文本、日志和错误均不回传完整密钥。查看不修改供应商库，输入新值才替换；留空保留原值。供应商库和共通模板保存于本机 SQLite，历史备份正文保留为文件，均可能含明文敏感信息；云端迁移包单独使用备份密码加密。

打开配置位置也通过校验来源与参数的专用 IPC 完成：界面只传工具和“目录 / 配置文件”目标，主进程从已生效的路径设置解析实际位置、检查存在性，再调用系统默认打开方式；不会接受界面传来的任意文件路径。

仅在用户明确应用供应商或恢复工具备份时写入目标工具文件。写入流程为解析、生成、回读校验、本地备份、外部修改检测和原子替换；验证失败会恢复原内容。敏感配置文件以仅当前用户可读写的权限创建，并拒绝替换符号链接。Codex 只操作所选目录中的 `config.toml`，自定义目录优先于 `CODEX_HOME`。应用供应商时共通模板纳入同一组备份；单独保存或恢复共通模板只修改应用数据目录。

## 共通配置与预览

Claude Code、Codex 各自的“功能配置 → 功能选项”管理对应工具的共通模板；每份由本机与 WSL 共用。页面直接展示并编辑 JSON/TOML 原文；两个工具原文标题旁的“快捷设置”默认收起。Claude Code 展开后显示思考强度下拉框与“隐藏 AI 签名”Switch；Codex 展开后显示 1M 与 Fast Switch，以及上下文窗口和压缩阈值。操作控件立即改变原文，直接编辑原文也会同步控件状态；折叠不丢弃草稿。格式无效时保留原文、禁用快捷控件和保存；阈值为空、非正整数或超过窗口时禁用保存并提示修正。Codex 的 `model_reasoning_effort` 仍直接在原文编辑。首次打开没有模板时显示空配置，读取和保存不要求安装工具或运行 WSL；可选的“从本机配置提取”才会读取本机工具文件，并排除供应商连接、模型、Header 和路由，Codex 的上下文、压缩阈值和 Fast 会保留在共通草稿中。其他环境字段中的密钥仍可在原文中编辑，模板本身也应视为敏感配置。

Claude Code 思考强度支持工具默认、`low`、`medium`、`high`、`xhigh`，选择工具默认会移除顶层 `effortLevel`。隐藏 AI 签名开启时写入 `attribution.commit = ""`、`attribution.pr = ""`、`attribution.sessionUrl = false`，同时屏蔽提交、PR 与会话链接；关闭时移除这三项，保留其他署名子字段。原文中的 `attribution: false` 同样显示为已开启，关闭会移除此字段；自定义签名在未操作开关时保持原样。保存及应用继续复用现有备份与署名恢复流程。

点击“保存共通配置”只备份并更新 AI Switch 数据库中的共享模板，不选择应用环境、不改写任何工具文件。应用供应商时组合连接、所选预设和该工具共享模板；接管状态按环境记录上次应用的模板，后续应用可清除模板中已删除的字段，并保留模板之外的对象子字段与权限规则。没有模板时保留当前通用内容。模板备份的恢复也只改应用内模板，后续应用供应商时生效。

本机与 WSL 共用 SQLite 中按基础工具保存的一条模板记录，原文存为 TEXT，显式空模板不会重新启用旧内容。启动时校验并备份旧 JSON，兼容固定名称、原 `.common.v2.json` 和早期本机/WSL 原文，直接导入数据库，不合并多个模板；成功后旧文件退出活动存储。

旧模板中属于模型或连接的字段会列出归属冲突；选择一个明确的供应商和模型后，使用“迁移归属字段”处理，再保存共通配置。迁移仅更新所选记录和共享模板，不读取或应用工具文件，也不把当前 Header 复制到其他供应商。旧单模型供应商转换为具有稳定 ID 的默认预设，新增选项保持未设置，保存使用当前无版本字段的供应商格式。

Codex 快捷开启 1M 会向共通草稿添加 `model_context_window = 1000000` 和 `model_auto_compact_token_limit = 900000`（已有阈值时保留），关闭时移除这两项；保存后重新应用供应商，会按模板删除规则清除之前应用的字段。Fast 开关分别写入 `service_tier = "fast"` / `"default"` 及 `features.fast_mode = true` / `false`，保留其他 features 子项。1M、Fast 和主思考强度均不属于模型预设，切换供应商或模型不会产生预设覆盖。旧模型预设中的对应选项兼容读取后忽略；旧接管记录释放这些字段的模型归属，不回写旧值覆盖共通模板。没有设置共通模板时保留工具文件已有值，可使用“从本机配置提取”将其带入共通草稿。Claude 关闭 1M 只移除模型名末尾的 `[1m]`，不强制降低原生上下文容量；现有工具文件中的 Fast 和压缩配置按未管理字段保留。Claude 原文中的 `attribution` 仍按配置内容应用，并在需要时保留接管前的署名子字段。

旧供应商库和备份中的计划模式思考强度、思考摘要、回复详细程度与 WebSocket 能力字段兼容读取后丢弃，不再由供应商预设应用。此前接管的模型字段在下次应用时按原有规则恢复，原生文件中自行维护的同名字段保留；自有 Codex provider 表中的旧 `supports_websockets` 会在重新应用时移除。读取旧记录本身不会修改工具配置。

共通配置编辑期间，如果工具文件、目录、模板或接管状态被修改，保存会拒绝覆盖并提示重新读取。恢复历史备份时，还原那份备份记录的工具配置原路径、共通模板与接管状态；旧备份没有接管状态时会清除较新的状态。不会回退整个供应商库，也不会访问其他历史关联文件。

工具页面 → 功能配置 → 配置路径仅展示可点击的路径和目录操作，不显示当前文件文本框。“打开文件”通过系统默认程序查看磁盘原文。外部修改后点击顶部刷新，会核对连接、预设选项及 Header 的签名。JSON/TOML 按语义合并，保留无关字段；Codex 的切换、保存和预览会重新排版 TOML，注释及原始排版不会保留，写前备份保留原文。

## 配置兼容性

### 安装检测与路径展示

主进程在本机 `PATH` 与原生安装、npm、WinGet、Homebrew 等常见位置查找 `claude` / `codex`，运行带超时的 `--version`，确认安装并读取 CLI 版本；本机版本输出无法识别时兼容 doctor 报告回退。确认安装后统一显示绿色“已安装 · 版本号”，认证、配置、网络等健康检查不参与安装判断且不展示。启动文件存在但版本无法识别、无法运行或权限受限时显示“安装需检查”，不会仅凭 `.claude` / `.codex` 目录判断安装成功。应用不发送模型生成请求、不自动修复，仅向界面返回安装信息与版本，原始报告不会进入快照或日志。

Codex 只检测和管理 Codex CLI，使用 PATH 与常见独立安装位置中的可运行 CLI。不扫描 Windows App 注册信息，也不使用桌面应用版本代替 CLI 版本。原生独立安装目录 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin` 也纳入查找，即使尚未加入当前进程的 PATH 仍可识别。

在 AI 应用页点击“重新检测”可重新扫描；标题栏不提供刷新按钮，AI 应用列表在本次运行期间保留检测结果。常规工具配置保存操作复用独立的短期缓存。本机入口检测运行 AI Switch 的操作系统中的 CLI；WSL 入口单独检测对应发行版中的 Linux CLI；仅通过 shell 别名、函数或其他自定义位置暴露的命令可能无法识别。新安装后若桌面进程的 PATH 尚未更新，请重启 AI Switch。

未检测到工具且默认配置文件不存在时，配置路径页隐藏推测的默认路径，提示先安装后刷新，或手动指定已有配置目录。已存在的配置文件、环境变量路径和自定义目录仍可管理，状态会同时说明 CLI 是否可用；配置文件尚不存在时不能打开或预览。检测本身不会创建工具目录或配置。

### Claude Code

- 默认目录：`~/.claude`，管理其中的 `settings.json`；Windows 中 `~` 表示 `%USERPROFILE%`。
- 若设置 `CLAUDE_CONFIG_DIR`，使用该目录下的 `settings.json`。
- 应用字段：顶层 `model`，以及 `env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_AUTH_TOKEN`。
- 适用于暴露 Anthropic Messages 格式的代理或网关；不管理 Bedrock、Vertex 或 Foundry 专用字段。
- 思考强度快捷设置提供工具默认及 low、medium、high、xhigh，不按模型名禁用选项；只保存顶层 `effortLevel`，选择工具默认则移除。AI Switch 不管理 `modelSettings.<model>.effortLevel`；实际适用范围由 Claude Code 版本和模型决定，按模型配置或启动参数可能覆盖顶层默认值，部分新版模型不读取用户级顶层默认值。字段含义参见 [Claude Code 官方配置参考](https://code.claude.com/docs/en/settings-reference#effortlevel)。
- 1M Switch 适用于直接输入的模型名及网关别名：开启在末尾添加一次 `[1m]`，关闭则移除。实际容量、强度降级和网关支持由 Claude Code 与服务端决定；不提供 Fast 和自动压缩表单，原有字段保留。

### Codex

- 默认目录：`~/.codex`，管理其中的 `config.toml`。
- 若设置 `CODEX_HOME`，使用该目录下的 `config.toml`。
- 地址、模型和 API Key 统一写入 `config.toml`；状态识别、配置校验和预览也仅读取这个工具文件。
- 应用字段：顶层 `model`、`model_provider`，以及 AI Switch 自有的 `model_providers` 表，其中 `base_url` 保存地址，`experimental_bearer_token` 保存 API Key。
- 自有 provider 显式设置 `requires_openai_auth = false`，使用该表中的直接令牌；不会生成 `env_key` 或命令认证配置。
- 自有 provider 固定使用 `wire_api = "responses"`，适用于 OpenAI Responses 兼容端点。
- 使用 `smol-toml` 校验并合并完整 TOML，保留未知字段并重新排版。若格式损坏或目标字段无法安全识别，会拒绝写入。
- 主思考强度只保存为顶层 `model_reasoning_effort`，对全部模型生效；实际支持级别由当前模型和网关决定。1M 和 Fast 统一在共通配置中管理：1M 开启后添加 `model_context_window = 1000000` 与 `model_auto_compact_token_limit`（默认 `900000`，支持 1 到 1,000,000 的整数），关闭后移除这两项；Fast 同步 `service_tier` 与 `features.fast_mode`。快捷设置只修改共通草稿，保存并应用供应商后写入工具文件。模型预设不再管理上述字段、计划模式思考强度、思考摘要和回复详细程度。字段含义参见 [Codex 官方配置参考](https://developers.openai.com/codex/config-reference/)。

在 Codex 页面重新应用已保存的供应商，会把供应商库中保存的 Key 连同地址、模型一起写入 TOML。应用不会自动访问、删除或修改 Codex 的其他认证文件；如果恢复的 TOML 未保存 Key，操作结果会提示重新应用已保存的供应商。

两个工具都可能在新会话启动时读取模型或凭据，因此应用或恢复后界面会提示新建或重启对应会话。更高优先级的命令行参数、项目配置、托管策略或进程环境变量仍可能覆盖用户配置文件。

## 文件位置、格式与云端迁移

应用数据根目录使用 Electron 的 `app.getPath('userData')`。Windows 通常是 `%APPDATA%\ai-switch`，macOS 通常是 `~/Library/Application Support/ai-switch`，Linux 通常是 `~/.config/ai-switch`；开发调试时可用 `AI_SWITCH_USER_DATA_DIR` 覆盖。

- `ai-switch.db`：供应商、工具连接、模型预设、Header、两份通用模板、主题及关闭偏好、S3 设置与密码、工具路径、接管状态、备份索引和待恢复操作。
- `ai-switch.db-wal`、`ai-switch.db-shm`：SQLite 管理的辅助文件，不能将单独复制主数据库当作完整备份。
- `backups/<tool-id>/<uuid>.backup`：工具文件和模板的本地操作备份正文，每个工具保留最近 20 份，索引进入数据库。
- `backups/configurations/<uuid>.json`：覆盖前的供应商和模板快照，以及旧 JSON 导入前的原文备份；普通快照可从备份页面恢复，迁移原文在目录中保留。
- `backups/database/<时间戳>-<uuid>.db`：已有数据库升级前，通过 SQLite 在线备份接口创建的完整恢复副本。

数据库迁移使用全局 `PRAGMA user_version`，不在业务记录或活动文件名中添加版本号。旧 `providers.json`、`settings.json`、`preferences.json`、模板、接管 JSON、备份索引及旧完成清单经过校验和原文备份后导入；导入和版本更新在同一个事务内完成，失败保留源文件，成功后清理旧活动文件。清理被占用或发现外部修改时保留并提示，后续只用数据库，不重复导入。详细边界见 [SQLite 存储说明](src/main/database/README.md) 和 [迁移维护说明](src/main/migrations/README.md)。

数据库及备份正文均可能含本机明文敏感信息。主题偏好从旧浏览器存储一次性导入，只保存“跟随系统 / 浅色 / 深色”的选择；系统实际颜色实时计算。大型文档、图片、附件、日志及 Electron 缓存继续使用文件。

Claude Code 实际工具文件是所选目录下的 `settings.json`，Codex 是 `config.toml`；供应商仅在用户点击“应用”时写入对应工具，密钥按工具协议写为明文。

云端绑定只保存连接信息，不自动上传或恢复。两个操作均使用整份覆盖：

- **保存到云端**：用本地完整供应商和两份通用模板替换 `<prefix>/backup.json.enc`，包含全部 API Key/Header；不读取旧存档、不比较修改时间、不合并内容，服务端最后成功提交者生效。
- **应用云端版本**：选择当前或历史存档，下载、解密并完整校验后创建本机快照，再在一个 SQLite 事务中登记快照索引并覆盖供应商和模板；本地新增、编辑、删除和 Key 修改全部以存档为准，空模板和空列表同样覆盖，写入失败整组回滚。

云端从数据库一致快照中导出供应商和通用模板，不上传整个数据库；主题、设备路径、字段接管状态、连接设置、本机密码和本地历史备份均不上传或覆盖。恢复不修改 Claude Code/Codex 的真实文件，完成后自行选择供应商应用；应用历史存档不自动回传云端。

备份文件使用 scrypt 派生密钥和 AES-256-GCM 整体加密，API Key 始终随文件备份，不另设字段加密或排除选项。新文件和正文不带格式版本标记，兼容读取旧 `.v1/.v2/.v3.json.enc` 加密存档；旧存档中的接管状态不导入，旧独立模板选择本机项（包括显式空值），仅缺少本机项时使用 WSL 项，不合并任何本地内容。

保存成功后写入 `<prefix>/backups/<UTC 时间戳>-<UUID>.json.enc` 供历史选择，按设置保留最近 1、3、5、10 或 20 份（默认 5）；固定当前对象另存，同一快照在列表中只展示一次。历史保存或清理失败提示当前存档已成功保存。上传响应丢失时通过本次存档标识查询确认，无法确认时提示结果待确认，不误报成功。分页列出旧、新命名的历史对象后清理，其他对象不受影响。

S3 凭据需要当前前缀的列出、读取、写入和删除权限；连接测试只检查访问及列表，不写入对象。存储桶自身的历史版本由其生命周期规则管理。

备份密码按现有约定保存在本机数据库的云端设置中，输入完成后自动保存，重启回填，清空可移除；密码不进入云端文件、对象元数据或日志，换设备恢复需提供对应密码。密码错误、格式损坏或下载失败不修改本地供应商和模板。

## 人工验证

仓库禁止添加任何测试代码、测试脚本或测试框架。开发调试应先把 `CLAUDE_CONFIG_DIR` 和 `CODEX_HOME` 指向临时目录，并使用占位 Key：

开发模式还支持用 `AI_SWITCH_USER_DATA_DIR` 把供应商库、路径设置和备份隔离到临时目录；生产构建会忽略这个覆盖。

1. 从本机和 WSL 四个工具首页分别点击“添加供应商”，确认进入设置中对应工具的共用表单；检查输入框聚焦、错误提示和小窗口滚动无重叠。
2. 分别进入 Claude Code、Codex 首页添加、编辑供应商，同名供应商可分别归属两个工具；在本机新增后确认 WSL 直接可见，反向新增、编辑和删除也同步可见。保存供应商不改工具文件，两个环境可分别应用不同供应商或模型；首页供应商行分别标记当前工具和其他环境的使用状态。重启后确认持久化和脱敏；旧 WSL 专属、同名冲突、同记录两环境配置不同的记录应在迁移后保留；云端恢复按整份覆盖处理。
3. 分别应用到 Claude Code、Codex，确认另一工具文件完全不变。
4. 检查原配置中的无关 JSON/TOML 内容仍然存在，并确认写入前生成备份。
5. 恢复备份，核对文件内容和当前供应商状态；再次恢复“恢复前”备份验证可撤销。
6. 人工制造路径不存在、损坏格式、只读文件和外部修改，确认应用不产生部分写入。
7. 全程不调用供应商 API，不在日志、截图或提交中使用真实 Key。
   使用占位 Key 核对列表与 JSON/TOML 完整配置均显示相同的前后缀脱敏结果；短 Key 不应完整显示，预览中的任意 Header 值、密码及其他令牌保持完全隐藏。分别使用不同长度的占位 Key，编辑已有供应商时确认密码输入框已经填入真实内容，首次进入即可选中和编辑；点击眼睛前后值、长度均不变，只改变显示方式。只查看后保存仍保留原值，编辑并保存后替换，清空后保留旧值，重新进入编辑页回填并默认隐藏。没有保存密钥时显示“输入 API Key”。读取失败时显示原因并可重试，不覆盖草稿或保存脱敏占位值。展开自定义请求头，确认值用普通文本输入框自动回填，修改名称时保留已载入的值，修改值、恢复原值及删除后保存正常，预览仍脱敏。
8. 配置目录选择 `.claude` / `.codex`；为 Codex 指定不同于 `CODEX_HOME` 的目录，确认只更新所选目录的 `config.toml`。旧版自定义文件路径应显示为父目录。
9. 共通配置显示两个工具页签和可编辑的 JSON/TOML 原文，两个工具标题旁均提供默认收起的“快捷设置”。Claude Code 展开后可选择工具默认或 low、medium、high、xhigh，隐藏 AI 签名同时写入空 commit、空 pr 和 false sessionUrl；核对直接编辑原文时控件同步、自定义签名未操作时保留、关闭移除三项且保留其他署名子字段，并兼容原文 `attribution: false`。标题与各操作按钮支持换行，内容未修改时保存仍可点击；原文损坏时仍可编辑修复且快捷控件和保存禁用，未知字段保留。保存只改变应用内模板和备份，两个环境工具文件不变；分别应用供应商后确认复用同一份模板。删除已应用的通用字段再保存、分别重新应用，确认字段不会重新出现；未安装工具或 WSL 不可用时仍可编辑保存模板。
10. 检查首页横向供应商行，每行一个，当前使用标签正确；顶部工具卡片不重复展示供应商、模型和 Base URL，保留安装版本、配置状态及错误提示。首页 Base URL 下方为“切换模型”下拉框，选项使用实际 API 模型 ID，重复 ID 通过模型选项区分，同时展示脱敏 API Key。确认“应用”“编辑”“更多”按钮间距为 12px，编辑可直接打开，更多菜单仅有删除且保留确认框；只有正在应用的行显示加载状态。模型表单只需填写 API 模型 ID，不显示示例模型名的 placeholder，无显示名称必填项；旧数据库升级及旧备份导入保留模型和默认引用，已移除的预设选项兼容读取后丢弃。首页不显示完整配置；编辑供应商时可展开完整配置文本框，没有预览模型选择，新增表单不显示该区域。应用非默认模型后进入编辑页，确认配置显示当前生效模型；编辑未启用的供应商或移除当前模型时使用默认模型，修改草稿后内容同步更新且真实文件不变。配置路径页只显示可点击路径，不显示当前文件文本框。
    在两工具的新增表单中展开高级连接选项，确认无需点击“添加请求头”即可输入名称和值；整行留空仍可保存，有值无名称时提示错误，编辑已有供应商时回填、保留与删除正常。Claude 1M 使用 Switch；Codex 供应商表单不显示 1M、Fast、计划思考、思考摘要、回复详细程度及 WebSocket 能力。进入 Codex 共通配置，确认标题旁“快捷设置”默认收起，展开后在原文上方显示开关与字段；关闭 1M 时字段置灰，开启时立即在 TOML 中添加 1000000 与默认 900000，可编辑阈值。验证原文与控件双向同步、折叠保留草稿、无效阈值禁用保存、未知字段保留。保存不改工具文件，应用后字段正确，切换供应商和模型继续使用相同共通值；关闭并保存、重新应用后清除对应字段，Fast 关闭写入 default/false，其他工具文件不变，恢复共通模板备份不直接写入工具文件。
11. 恢复共通模板修改前的备份，确认只还原应用内共享模板，工具文件不变；首次保存前不存在共享模板时恢复应撤销该保存，不重新启用旧模板。旧工具备份仍恢复原工具文件，旧模板路径映射到共享模板，恢复前创建安全备份。
12. 编辑期间从外部修改共享模板，确认保存拒绝覆盖并可重新读取；输入损坏的 JSON/TOML 或供应商字段时确认有明确反馈。仅改变目标工具文件或目录不应阻止保存应用内模板。
13. 重新应用 Codex 供应商，确认 TOML 自有表包含 `experimental_bearer_token` 和 `requires_openai_auth = false`；保存共通配置后密钥仍保留，预览中密钥始终脱敏。
14. 恢复本地历史备份，确认只恢复工具配置与共通模板，其他关联文件没有被访问或修改；恢复不含 TOML 密钥的备份时有重新应用供应商的提示。
15. 在配置路径页分别点击两工具的目录路径、文件路径及打开按钮，确认使用当前已保存目录和系统默认程序；目录和文件路径各显示一次，没有路径输入框和文件预览文本框。点击“更换目录”从对应工具的当前目录打开，目录不存在时定位最近存在的上级目录；取消选择不改变路径。检查路径不存在、无权限及未设置默认程序的反馈；打开和预览均不创建文件或备份。
16. 在应用设置中选择“最小化到系统托盘”，点击窗口关闭按钮，确认窗口隐藏且进程仍在；左键、双击图标或再次启动应用恢复原窗口。右键菜单仅显示“退出应用程序”，点击后进程退出且图标消失。重启确认设置保留；切回“直接退出”后关闭窗口，确认进程退出。托盘创建失败时应提示并回退到直接退出。
17. 分别检查可运行 CLI、未安装 CLI、启动文件存在但版本读取失败时的状态；已有配置但没有 CLI 时应同时显示配置状态和“未检测到安装”。安装或修复后点击刷新确认状态更新，CLI 检测不调用付费 API。
