# 会话管理

`SessionService` 处理公共查询和删除确认；工具差异由独立适配器实现。渲染进程只传递数据源、查询参数、不透明会话键和短期确认令牌，不接受任意文件删除路径。

- `types.ts` / `adapters.ts`：适配器契约和注册；Claude / Codex 本地与 WSL 复用各自实现，数据目录、缓存键和删除范围按数据源隔离。
- `claude.ts`：Claude 事件解析、分支重建、项目索引、运行标记、正文与附件删除及共享历史清理。
- `codex.ts`：Codex 日志解析、镜像事件去重、原生列表 / 正文 / 删除接口及派生会话关系。列表包含归档、子代理及全部供应商。
- `copilot-cli.ts`：Copilot CLI 日志与原生列表合并、消息读取、本地会话删除，不操作远端副本。
- `vscode.ts`：VS Code 工作区和无项目窗口的 JSON / JSONL 读取及增量重放、SQLite 标题索引、进程检查和清理。普通扫描隐藏无请求的空会话；清空扫描包含空会话与草稿，不根据标题判断空记录。
- `messages.ts` / `storage.ts` / `files.ts`：通用文本归一化、JSONL 读取、文件指纹、最近写入检查和路径边界校验。
- `service.ts`：目录合并、查询缓存、搜索、分页、正文缓存限额、删除计划与部分失败反馈。通过适配器调用工具操作，不解析工具格式。
- `native-rpc.ts`：Codex stdio JSONL JSON-RPC；Copilot CLI 使用官方 SDK 相同的 Content-Length JSON-RPC。仅查询已有会话和执行明确确认的删除，不调用启动、恢复或发送提示的方法。短期复用进程，空闲、超时和应用退出时关闭。
- `ipc.ts`：校验调用来源、枚举及输入范围，串行化预览和删除，操作期间阻止退出应用。

前端 `features/sessions/` 中每个工具有独立页面，组合公共 `SessionBrowser`、`SessionDeleteDialog` 与 `SessionConversation`。入口在各工具首页；搜索、筛选与选择状态按数据源重新创建。VS Code 与 Copilot CLI 通过显式入口切换，保持两类记录和操作独立。

“清空全部”不复用列表查询或选择结果，而是重新完整扫描当前数据源的默认及已配置目录。读取不完整、目录不可读或 CLI 列表不可用时停止。计划保存在主进程，五分钟后过期，包含数据目录签名与所有会话版本；确认前重新扫描并校验范围和版本，再检查运行状态。确认后出现新记录、目录变化或新子会话时不开始删除。清空用与单个删除相同的适配器逐项处理，不递归清空工具根目录，不自动创建备份。

Claude 没有满足要求的单会话永久删除 API：`purge` 会影响整个项目，而后台 `rm` 会保留正文。因此仅操作经过验证的目标正文及会话专用目录，清理匹配 ID 的历史索引，不删除项目记忆。正文删除失败时保留关联数据；正文已删但清理失败时，返回成功及明确的清理警告。共享历史采用文件指纹检查与原子替换。

Codex / Copilot CLI 不直接更新工具数据库，完整列表接口不可用时禁止删除。Codex 原生删除会级联派生会话，预览必须覆盖已发现子树。VS Code 删除正文后清理 SQLite 索引，要求退出所有编辑器窗口，避免缓存重新写回。运行状态检查是尽力检测，原工具不提供统一外部文件锁，无法保证其他进程同时写入时的跨进程事务；删除前应关闭目标会话。操作逐项报告失败和清理警告，删除已成功的条目不会回滚。
