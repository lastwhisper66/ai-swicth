# 会话管理

`SessionService` 负责独立于供应商配置的会话生命周期。界面只传递已列出的不透明会话键；任何删除都必须先生成主进程保存的短期计划，再确认计划令牌。

- `service.ts`：数据根目录、会话目录缓存、全文检索、分页、内存容量控制、删除预览及批量结果。Codex 会话来源显式包含子代理，供应商范围为全部；删除前重新发现派生关系，使用一次根会话删除请求覆盖已确认的子树。
- `files.ts`：限制目录扫描深度、不跟随符号链接、校验实际路径归属、文件指纹、JSONL 采样及有大小限制的完整读取。
- `messages.ts`：将 Claude、Codex 和 Copilot 持久化记录转换为统一对话消息。Claude 重建当前分支；Codex 兼容协议消息和旧版事件消息并消除相邻镜像记录。原始工具输出不执行。
- `native-rpc.ts`：Codex stdio JSONL JSON-RPC；Copilot CLI 使用官方 SDK 相同的 Content-Length JSON-RPC。仅查询已有会话和执行明确确认的删除，不调用启动、恢复或发送提示的方法。短期复用进程，空闲、超时和应用退出时关闭。
- `vscode.ts`：读取 VS Code 工作区 `chatSessions` 的 JSON / JSONL 会话和 `state.vscdb` 标题索引，重放增量操作日志，按会话清理正文和索引；删除前检查所有 VS Code 进程。
- `ipc.ts`：来源验证、参数范围及枚举检查；会话只检查默认数据根目录和工具已配置的数据根目录，去重后合并扫描。

Claude 没有满足要求的单会话永久删除 API：`purge` 会影响整个项目，而后台 `rm` 会保留正文。因此仅操作经过验证的目标正文及会话专用目录，清理匹配 ID 的历史索引，不删除项目记忆。正文删除失败时保留关联数据；正文已删但清理失败时，返回成功及明确的清理警告。共享历史采用文件指纹检查与原子替换；原工具没有外部文件锁协议，仍要求关闭目标会话，无法保证其他进程同时写入时的跨进程事务。

Codex / Copilot CLI 不直接更新工具数据库，完整列表接口不可用时禁止删除。Codex 原生删除会级联派生会话；用户确认范围必须覆盖已发现子树，确认后出现新子会话则停止。VS Code 会话删除正文后清理 SQLite 索引，要求编辑器退出。运行状态检查是尽力检测，其他进程仍打开的会话应先关闭。

手工验证使用独立应用数据目录、临时工具根目录和虚构对话。遵守仓库约定，不新增测试代码、测试脚本或测试框架，不删除真实历史。
