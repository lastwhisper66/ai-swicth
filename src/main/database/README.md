# 本机 SQLite 存储

主进程通过 `better-sqlite3` 独占管理 `<userData>/ai-switch.db`。供应商、工具连接、模型预设和 Header 使用关联表；通用模板保存原文，灵活选项使用经过领域校验的 JSON 列。主题、关闭行为、S3 连接、密码、工具路径和接管状态仅限本机保存。AI 应用的侧栏显示开关、各 WSL 发行版的 shell 与应用表格顺序保存在 `device_settings.applications`，由领域服务校验，不随供应商云备份迁移。旧设置没有顺序时使用目录默认顺序；新增工具追加末尾，移除的工具从顺序中过滤。旧设置中的 flag 字段被忽略，后续保存只写入 shell，无需数据库迁移。

迁移进度采用 `PRAGMA user_version`，步骤及维护说明在 [`../migrations/`](../migrations/README.md)。启用外键、WAL 和完整同步；短事务内只执行同步数据库操作，不跨越网络请求或异步文件操作。默认模型使用延迟外键，整组替换时一并检查引用。备份和接管状态中的历史供应商 ID 不建立业务外键，避免删除供应商时丢失历史或阻止云端整份覆盖。

`index.ts` 提供供应商记录、设置、模板/接管记录和备份索引访问。应用记录使用明确的 `template:<基础工具>`、`state:<完整工具>` 标识，不伪装成本地 JSON 路径。渲染进程只通过受限 IPC 调用业务方法，不直接执行 SQL。

数据库第 3 步迁移移除 `model_presets.name`，业务记录及导出只保留模型记录 ID、API 模型 ID 和选项。供应商写入兼容第 2 步旧 JSON 导入期间仍存在名称列的结构，迁移完成后不再保存模型显示名称。

`configuration-targets.ts` 协调数据库记录与外部工具文件：写前备份并登记待恢复操作，原子替换工具文件并读回校验，最后事务提交接管状态和操作完成记录。应用中断后先恢复未完成操作；发现后续外部修改时保留资料并阻止自动覆盖。数据库事务不能代替文件写入回滚。

备份正文和恢复副本仍为文件，数据库只保存索引；先写正文并校验，再提交索引，清理时先移除索引再删除正文。单独复制数据库不能包含所有历史备份。运行中数据库的恢复副本通过 SQLite 在线备份接口生成，不直接复制 `ai-switch.db`；`-wal`、`-shm` 是 SQLite 管理的辅助文件。

云端从一致的数据库读事务中导出供应商（始终含 API Key/Header）和两份通用模板，再用备份密码整体加密，不上传整个数据库。应用存档前保存本机配置快照，再在一个事务中登记索引、替换供应商和模板；设置、主题、路径、接管状态及真实工具文件不受覆盖。

当前依赖 `better-sqlite3` 13 提供 Node-API 预编译二进制，支持当前 Node.js/Electron；不强制依赖本机 C++ 编译工具链。安装后只执行 `install-electron`，不再通过 `electron-builder install-app-deps` 强制重建原生模块；Electron Builder 保持 `npmRebuild: false` 并显式解包该依赖。升级依赖后需要重新核对二进制兼容和打包加载，不能只检查 TypeScript 构建。

SQLite 本地文件、备份正文及本机保存的密码可能包含明文敏感信息；密钥只在主进程处理，日志和错误不输出正文。仅可移植云端存档使用现有 scrypt + AES-256-GCM 整体加密。
