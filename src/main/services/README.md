# 配置切换服务

`app-settings.ts` 单独持久化窗口关闭行为，默认直接退出；`tool-installation.ts` 在本机 PATH 与常见安装位置查找 CLI，并通过有超时的版本命令确认可运行性。`codex-cli-location.ts` 补充 Windows 原生 CLI 目录与桌面版内置 CLI 位置：优先使用独立 CLI，找不到可运行版本时才查询当前用户的应用包注册位置，并读取内置 CLI 的版本，不显示桌面应用包版本。安装状态与 `tool-status.ts` 的配置状态独立，手动刷新强制重新检测，常规快照复用短期缓存。检测不会创建工具目录或配置文件。

在此协调目录解析、共通配置、完整预览、切换、备份、原子写入和恢复。路径设置保存配置目录，并兼容旧版文件路径。共通模板按工具以明文 JSON/TOML 保存；`managed-state.ts` 记录模型选项接管前值、应用值、所选预设签名及署名恢复状态。工具文件、模板、接管状态按组备份，写前检测外部修改，逐文件原子替换、读回校验，失败回滚。切回默认只恢复未被外部修改的接管字段。旧备份缺少状态时清除较新的状态，不回退整个供应商库。

`configuration-migration.ts` 将旧共通模板中的归属字段迁入明确指定的供应商与预设，写前备份，失败回滚；Claude 仅迁移 Header 和路由，思考强度留在共通配置，Fast 和自动压缩按未管理字段保留；Codex 仍迁移模型选项。不应用工具文件、不广播至其他供应商。Codex 的 API Key、地址和模型只写 `config.toml`。预览在主进程脱敏 Key 和任意命名的 Header 值后返回，不写文件。

`config-preview.ts` 对 API Key、Claude 的 `ANTHROPIC_AUTH_TOKEN` 和 Codex 的 `experimental_bearer_token` 复用供应商摘要的前后缀脱敏规则；其他令牌、密码和 Header 值保持完全隐藏。已知密钥在其他字符串中的副本也会脱敏，采用单次匹配替换，避免再次处理已生成的脱敏内容。

旧版多文件备份先完成正文完整性校验，再仅选取工具配置及当前应用对应的共通模板进行恢复，不读取或写入其他历史关联文件。旧 TOML 未包含密钥时提示重新应用已保存的供应商。

S3 兼容云端备份使用版本 2 文档，包含供应商全部预设、Key/Header、共通模板和接管状态，加密为一个带时间戳及 UUID 的 `.v2.json.enc` 对象，兼容恢复旧 v1。恢复前完整校验，恢复失败回滚，不自动应用工具文件；接管状态中的原目标路径不同时不套用原记录。保留数量可选 1、3、5、10、20，默认 5；上传成功后分页列出 v1/v2 和旧固定名称备份，按 `LastModified` 清理超额最旧对象，保留刚上传的对象。清理不下载正文或访问历史版本，列表失败和删除失败分别提示。备份密码明文保存于本机设置，不进入云端文档或元数据。

多文件写入需要失败恢复；开发时使用临时目录，只有用户发起应用供应商、保存并应用共通配置或恢复操作才修改真实工具配置。
