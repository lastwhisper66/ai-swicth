# 配置切换服务

`app-settings.ts` 单独持久化窗口关闭行为，默认直接退出；`tool-installation.ts` 在本机 PATH 与常见安装位置查找 CLI，并通过有超时的版本命令确认可运行性。`codex-cli-location.ts` 补充 Windows 原生 CLI 目录与桌面版内置 CLI 位置：优先使用独立 CLI，找不到可运行版本时才查询当前用户的应用包注册位置，并读取内置 CLI 的版本，不显示桌面应用包版本。安装状态与 `tool-status.ts` 的配置状态独立，手动刷新强制重新检测，常规快照复用短期缓存。检测不会创建工具目录或配置文件。

在此协调目录解析、共通配置、完整预览、切换、备份、原子写入和恢复。路径设置保存配置目录，并兼容旧版文件路径。共通模板按工具以明文 JSON/TOML 内容保存，保存立即应用，切换供应商时复用完整模板；模板与工具配置一起备份及恢复。Codex 的 API Key、地址和模型统一存入 `config.toml`，仅访问这一个工具配置文件。预览在主进程脱敏后返回，不写入文件。

旧版多文件备份先完成正文完整性校验，再仅选取工具配置及当前应用对应的共通模板进行恢复，不读取或写入其他历史关联文件。旧 TOML 未包含密钥时提示重新应用已保存的供应商。

S3 兼容云端备份每次将供应商与共通模板加密为一个带时间戳和 UUID 的对象。保留数量可选 1、3、5、10、20 份，默认 5 份；上传成功后分页列出当前备份目录下的 `.v1.json.enc` 文件和旧固定名称备份，仅按 S3 的 `LastModified` 从旧到新排序，直接删除超额的最旧文件并保留刚上传的备份，恢复读取最新一份。清理不读取文件正文、文件名中的时间格式或历史版本，未超限时不发送删除请求；S3 底层历史版本由存储桶生命周期管理。列表检查失败与实际删除失败分别返回包含原因的提示，不掩盖已上传成功的结果。备份密码通过独立 IPC 自动保存到本机明文设置并回填输入框，连接设置的保存不会清除密码；密码不进入云端迁移文档或元数据。

多文件写入需要失败恢复；开发时使用临时目录，只有用户发起应用供应商、保存并应用共通配置或恢复操作才修改真实工具配置。
