# 配置切换服务

`app-settings.ts` 单独持久化窗口关闭行为，默认直接退出；`tool-installation.ts` 在本机 PATH 与常见安装位置查找 CLI，并通过有超时的 claude doctor / codex doctor --json 确认安装，版本直接取自报告。`codex-cli-location.ts` 补充 Windows 原生 CLI 目录与桌面版内置 CLI 位置：优先使用独立 CLI，找不到可识别 doctor 报告的 CLI 时才查询当前用户的应用包注册位置，并读取内置 CLI 的 doctor 报告，不显示桌面应用包版本。安装状态与 `tool-status.ts` 的配置状态独立，手动刷新强制重新检测，常规快照复用短期缓存。检测不会创建工具目录或配置文件。

在此协调目录解析、共通配置、完整预览、切换、备份、原子写入和恢复。路径设置保存配置目录，并兼容旧版文件路径。共通模板按基础工具保存在应用数据目录中，以 JSON 容器保存明文 JSON/TOML 原文；`managed-state.ts` 按环境记录模型选项接管前值、应用值、所选预设签名、上次应用的共通模板及署名恢复状态。应用供应商时，工具文件、共享模板、接管状态按组备份，写前检测外部修改，逐文件原子替换、读回校验，失败回滚。旧备份缺少状态时清除较新的状态，不回退整个供应商库。

供应商和共通模板按基础工具共用：切换、草稿预览、当前状态匹配和共通字段迁移均通过 `baseToolId` 读取同一份供应商模型、Header、路由及连接能力。目标路径、适配器和接管状态使用完整工具标识；应用到本机或 WSL 仅更新所选环境。保存供应商只更新共用库；保存共通配置只校验、备份并更新应用内模板，不访问目标工具文件，不要求工具或 WSL 可用。共通模板使用独立的 `template` 备份类型，恢复也仅更新应用内模板。云端恢复兼容旧 WSL 供应商和模板记录。

`common-config.ts` 将本机与 WSL 映射到同一个 `<base-tool-id>.common.v2.json`。缺少新模板时只读合并两边旧 `.common.json`，保留独有字段，冲突采用本机值并反馈，原文件保持不变。新容器的显式空内容阻止云端恢复空模板后再次启用旧文件。读取快照包含新旧来源文件，保存和应用前检查来源未被外部修改；同一基础工具共用操作锁。旧本地备份先校验原始校验和，再把旧模板映射、编码为共享模板恢复。

`configuration-migration.ts` 将共通模板中的连接或模型归属字段迁入明确指定的供应商与预设，写前备份，失败回滚；Claude 仅迁移 Header 和路由，Fast 和自动压缩按未管理字段保留；Codex 迁移模型选项。两个工具的主思考强度都保留为共通顶层字段。迁移只访问应用内供应商和共享模板，不读取或应用工具文件、不广播至其他供应商。Codex 的 API Key、地址和模型只写 `config.toml`。预览在主进程脱敏 Key 和任意命名的 Header 值后返回，不写文件。

`config-preview.ts` 对 API Key、Claude 的 `ANTHROPIC_AUTH_TOKEN` 和 Codex 的 `experimental_bearer_token` 复用供应商摘要的前后缀脱敏规则；其他令牌、密码和 Header 值保持完全隐藏。已知密钥在其他字符串中的副本也会脱敏，采用单次匹配替换，避免再次处理已生成的脱敏内容。

旧版多文件备份先完成正文完整性校验，再仅选取工具配置及当前应用对应的共通模板进行恢复，不读取或写入其他历史关联文件。旧 TOML 未包含密钥时提示重新应用已保存的供应商。

S3 兼容云端备份使用版本 3 文档，包含供应商全部预设、Key/Header、共通模板和接管状态，加密为一个带时间戳及 UUID 的 `.v3.json.enc` 对象，兼容恢复旧 v1/v2。为保持文档兼容性，共通模板的本机与 WSL 项携带相同原文，计数按两个基础工具计算；恢复旧独立模板时先合并，再按基础工具写入一次，缺少的接管状态按空值导入。恢复前完整校验，恢复失败回滚，不自动应用工具文件；接管状态中的原目标路径不同时不套用原记录。保留数量可选 1、3、5、10、20，默认 5；上传成功后分页列出 v1/v2/v3 和旧固定名称备份，按 `LastModified` 清理超额最旧对象，保留刚上传的对象。清理不下载正文或访问历史版本，列表失败和删除失败分别提示。备份密码明文保存于本机设置，不进入云端文档或元数据。

多文件写入需要失败恢复；开发时使用临时目录，只有用户发起应用供应商或恢复工具备份才修改真实工具配置。保存和恢复共通模板只修改应用数据目录。

`wsl-runtime.ts` 统一封装 wsl.exe、用户 shell 初始化、白名单环境变量读取与命令执行，不依赖工具标识或包管理器。先在 Linux HOME 中启动用户自己的交互式登录 shell，再在继承环境中按 PATH 定位可执行文件（含 shim）；不补写固定安装目录，不加载特定包管理器脚本。命令及参数分别传入，统一处理 shell 转义、超时、退出码及输出边界；初始化输出与工具报告分开，未找到命令和诊断失败分别反馈。

`wsl.ts` 负责工具配置目录映射、环境缓存与调用 doctor，不再处理底层命令执行。npm、原生安装及版本管理器只要在用户 PATH 中提供可执行文件即可共用同一流程；alias / function 和未加入 PATH 的安装不自动识别。WSL 不可用时按入口反馈，不阻断本机状态。WSL 路径只接受 wsl.localhost / wsl$ 共享，四个入口分别持久化工具状态和备份，共用两份模板；恢复工具配置使用备份原路径，写前确认原发行版可用。首次写入可创建缺失的 WSL 目录，所有读操作均不创建文件。

`tool-diagnostics.ts` 统一解析 doctor 报告，仅返回安装版本。Codex 读取脱敏 JSON 中的 codexVersion 与 installation 字段，Claude 读取 Running / Currently running 等安装字段；忽略退出码所表达的整体健康状态以及认证、网络等其他检查项。确认安装后一律显示绿色“已安装 · 版本号”，不返回健康摘要或展示诊断警告。完整诊断报告不经 IPC 返回、不写入日志，不运行自动修复。
