# 配置切换服务

`app-settings.ts` 在 SQLite 中持久化主题、窗口关闭行为和云端连接设置，默认关闭直接退出；`tool-installation.ts` 在本机 PATH 与常见安装位置查找 CLI，并通过有超时的 claude doctor / codex doctor --json 确认安装，版本直接取自报告。`codex-cli-location.ts` 补充 Windows 原生 CLI 目录与桌面版内置 CLI 位置：优先使用独立 CLI，找不到可识别 doctor 报告的 CLI 时才查询当前用户的应用包注册位置，并读取内置 CLI 的 doctor 报告，不显示桌面应用包版本。安装状态与 `tool-status.ts` 的配置状态独立，手动刷新强制重新检测，常规快照复用短期缓存。检测不会创建工具目录或配置文件。

在此协调目录解析、共通配置、完整预览、切换、备份、原子写入和恢复。路径设置保存配置目录，并兼容旧版文件路径。共通模板按基础工具保存在 SQLite 的 TEXT 列中，保留 JSON/TOML 原文；`managed-state.ts` 按环境记录模型选项接管前值、应用值、所选预设签名、上次应用的共通模板及署名恢复状态。应用供应商时，工具文件、共享模板、接管状态按组备份，写前检测外部修改，由 `database/configuration-targets.ts` 登记待恢复操作、原子替换工具文件、读回校验后事务提交接管状态；失败回滚，启动时恢复中断操作。旧备份缺少状态时清除较新的状态，不回退整个供应商库。

供应商和共通模板按基础工具共用：切换、草稿预览、当前状态匹配和共通字段迁移均通过 `baseToolId` 读取同一份供应商模型、Header、路由及连接能力。目标路径、适配器和接管状态使用完整工具标识；应用到本机或 WSL 仅更新所选环境。保存供应商只更新共用库；保存共通配置只校验、备份并更新应用内模板，不访问目标工具文件，不要求工具或 WSL 可用。共通模板使用独立的 `template` 备份类型，恢复也仅更新应用内模板。云端恢复兼容旧 WSL 供应商和模板记录。

`common-config.ts` 将本机与 WSL 映射到同一条基础工具模板记录，显式空内容也是最终值。启动升级迁移由 [`../migrations/`](../migrations/README.md) 的有序步骤负责，通过 SQLite `user_version` 跳过已完成步骤；旧 JSON 校验、备份后直接导入，不再生成新活动 JSON。旧操作备份先校验原始正文，再映射为数据库模板或接管状态引用。

`configuration-fields.ts` 处理用户主动执行的归属字段移动，不参与启动升级迁移：将共通模板中的连接或模型字段移入明确指定的供应商与预设，写前备份，失败回滚；Claude 仅迁移 Header 和路由，Fast 和自动压缩按未管理字段保留；Codex 迁移模型选项。两个工具的主思考强度都保留为共通顶层字段。迁移只访问应用内供应商和共享模板，不读取或应用工具文件、不广播至其他供应商。Codex 的 API Key、地址和模型只写 `config.toml`。预览在主进程脱敏 Key 和任意命名的 Header 值后返回，不写文件。

`config-preview.ts` 对 API Key、Claude 的 `ANTHROPIC_AUTH_TOKEN` 和 Codex 的 `experimental_bearer_token` 复用供应商摘要的前后缀脱敏规则；其他令牌、密码和 Header 值保持完全隐藏。已知密钥在其他字符串中的副本也会脱敏，采用单次匹配替换，避免再次处理已生成的脱敏内容。

旧版多文件备份先完成正文完整性校验，再仅选取工具配置及当前应用对应的共通模板进行恢复，不读取或写入其他历史关联文件。旧 TOML 未包含密钥时提示重新应用已保存的供应商。

S3 云端备份按方向整份覆盖：上传供应商（含 Key/Header）与两份通用模板到固定 `backup.json.enc`，服务端最后成功提交者生效；应用所选当前/历史存档时覆盖本地供应商和模板，不合并。当前供应商通过工具文件读取匹配，路径设置、主题、接管状态和密码只留本机，恢复不写真实工具文件。完整文件继续用 scrypt + AES-256-GCM 加密，取消新存档格式版本字段与文件名后缀，兼容旧加密文档，忽略旧接管状态。历史独立模板以本机项为准（含 null），不合并。

`configuration-archives.ts` 保存带校验和的覆盖前快照，备份页面可主动恢复；恢复前再备份，正文先写入独立文件并校验，再在同一个 SQLite 事务中登记索引和替换供应商、模板；失败整组回滚。云端上传从短的数据库读事务取得一致快照，不直接上传运行中的数据库。控制器操作锁串行化供应商、模板及恢复，避免应用途中编辑。云端提供存档列表，成功保存后保留带时间戳和 UUID 的历史副本，按用户设定清理；当前对象单独保存。响应丢失时查询本次标识核实提交结果，历史副本或清理失败不会将已成功保存报为失败。

多文件写入需要失败恢复；开发时使用临时目录，只有用户发起应用供应商或恢复工具备份才修改真实工具配置。保存和恢复共通模板只修改应用数据目录。

`wsl-runtime.ts` 统一封装 wsl.exe、用户 shell 初始化、白名单环境变量读取与命令执行，不依赖工具标识或包管理器。先在 Linux HOME 中启动用户自己的交互式登录 shell，再在继承环境中按 PATH 定位可执行文件（含 shim）；不补写固定安装目录，不加载特定包管理器脚本。命令及参数分别传入，统一处理 shell 转义、超时、退出码及输出边界；初始化输出与工具报告分开，未找到命令和诊断失败分别反馈。

`wsl.ts` 负责工具配置目录映射、环境缓存与调用 doctor，不再处理底层命令执行。npm、原生安装及版本管理器只要在用户 PATH 中提供可执行文件即可共用同一流程；alias / function 和未加入 PATH 的安装不自动识别。WSL 不可用时按入口反馈，不阻断本机状态。WSL 路径只接受 wsl.localhost / wsl$ 共享，四个入口分别持久化工具状态和备份，共用两份模板；恢复工具配置使用备份原路径，写前确认原发行版可用。首次写入可创建缺失的 WSL 目录，所有读操作均不创建文件。

`tool-diagnostics.ts` 统一解析 doctor 报告，仅返回安装版本。Codex 读取脱敏 JSON 中的 codexVersion 与 installation 字段，Claude 读取 Running / Currently running 等安装字段；忽略退出码所表达的整体健康状态以及认证、网络等其他检查项。确认安装后一律显示绿色“已安装 · 版本号”，不返回健康摘要或展示诊断警告。完整诊断报告不经 IPC 返回、不写入日志，不运行自动修复。
