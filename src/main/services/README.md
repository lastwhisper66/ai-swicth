# 配置切换服务

`app-settings.ts` 在 SQLite 中持久化主题、窗口关闭行为和云端连接设置，默认关闭直接退出；`tool-installation.ts` 在本机 PATH 与常见安装位置查找 CLI，通过有超时的 `--version` 确认安装，本机版本输出无法识别时兼容 doctor 报告回退。`codex-cli-location.ts` 只补充 Windows 独立 CLI 常见目录，不查询 Windows App 注册信息。安装状态与 `tool-status.ts` 的配置状态独立，手动刷新强制重新检测，常规快照复用短期缓存。检测不会创建工具目录或配置文件。

`application-preferences.ts` 使用既有 `device_settings` 保存四个供应商入口的显示开关、按发行版区分的 shell 和全部应用的排列顺序，无需修改数据库结构。顺序写入前经 IPC 校验实例白名单、完整性及唯一性；读取旧设置时补入默认顺序，新增目录项追加末尾，移除的目录项忽略。旧偏好中的 flag 字段不再校验或使用，shell 设置继续保留，下次保存时不写入 flag。`application-management.ts` 从 `shared/applications.ts` 读取工具目录，统一管理 Claude Code、Codex CLI、Gemini CLI、Grok Build 的 npm 包、版本查询、npm 来源核对和后台任务。目前六个环境实例包括四个工具的本机安装和 Claude Code、Codex 的 WSL 安装；供应商页面映射可选，不把只有安装管理的工具加入供应商模型。目录中集中维护包名、命令、版本参数和解析规则，IPC 白名单及页面列表随实例目录派生。安装和卸载固定 npm 可执行文件及 prefix；通过全局包清单、manifest bin 与启动文件实际位置确认当前 CLI 的归属，Windows 兼容 npm cmd shim，WSL 通过 readlink 对比。来源不明或不同副本时禁止更新和卸载。安装、更新和卸载使用环境写锁；检查更新按环境分别登记正在检查的应用，允许同一环境的不同工具并行检查，拒绝重复检查及与环境写操作重叠。shell 在该环境存在检查或写操作时锁定，供应商操作仍使用原来的独立控制器锁。

启动通过 `app:get-bootstrap` 只读取本地供应商、设置、备份及应用信息，刷新环境缓存但不执行 CLI 或 WSL 检测。渲染层 `use-app-bootstrap.ts` 先展示完整框架，再读取本地数据，随后通过 `tools:get-status` 为四个工具分别发起并行请求；每项完成即填入对应状态，尚未返回的状态保持 undefined。单项失败提供重试，其他工具和设置不受阻塞。请求标识与初始化版本用于丢弃迟到响应；完整操作快照会使旧请求失效，安装任务结果覆盖同时进行的旧状态检测。原有完整快照接口继续用于主动刷新和业务操作结果。

渲染层 `use-applications.ts` 只管理当前页面的请求状态，不缓存跨页面的检测结果。进入页面先从共享目录显示全部工具、图标和表格操作位置，路径及版本使用 Spinner。所有行位于一张表格中，按照偏好中的顺序渲染；`SortableApplicationTable.tsx` 使用新版 `@dnd-kit/react` 的 DragDropProvider 和 `@dnd-kit/react/sortable` 的 useSortable，提供六点手柄、垂直排序、实时让位及键盘操作，不使用 Legacy API。一个 tbody 包含应用主行及附加行，库内置的乐观排序与动画直接移动整组 DOM；通过 source.initialIndex 和 source.index 确定实际移动，不能比较 source / target ID，因为乐观排序时二者会指向同一项。DragOverlay 通过库内置的顶层反馈展示固定尺寸预览，原行为虚线落点，并根据响应式 source.index 提示目标序号。预览在拖动前准备，保留至落位动画结束，不参与拖动注册且不可交互，shell 控件使用独立 ID；减少动态效果时禁用动画。放下时先同步提交 React 行顺序，再异步保存，确保快速失败时也可回退乐观 DOM 变更；取消由库恢复原位置且不写入，安装状态变化不会移动行。配置 sensors / plugins 时扩展默认项，保留键盘、自动滚动及无障碍支持；Tailwind 层级将 dnd-kit 放在最前，以允许主题样式覆盖 popover 默认样式。`getApplications` 接收 requestId，主进程在一次环境刷新后并行检测各实例，各自完成时通过 `applications:detected` 向请求窗口发送带 requestId 的单行结果；每个实例只等待自身的检测和对应包的版本查询。同包共享一次进行中的 npm 请求，最终列表响应只用于核对与完成反馈，不阻止逐行展示。界面每收到一行就在原位置更新并开放该行操作，尚未确认的行继续占位，加载状态仅在行内展示；全局 refreshing 只禁用重复的全量刷新，顶部不显示总进度或加载动画。页面离开或 shell 变更时清理订阅，旧批次的结果和最终响应均不会覆盖新批次。

“详情”和“检查更新”分列并使用带 Tooltip 的 outline 图标按钮，更多菜单只保留卸载。页面单独跟踪各工具待启动的检查，环境内其他检查不会禁用当前工具的检查按钮。`ApplicationDetailsDialog.tsx` 使用 Dialog 和 Tabs 展示安装信息及当前运行期间的记录，限制弹窗高度、内部滚动，记录按时间倒序并每页展示 5 条；翻页重置滚动位置，历史缩短时收敛到有效页码，关闭或切换工具后重置弹窗状态。弹窗目标保存在页面中，单项结果更新时仍保持打开。

安装、更新和卸载结束后，以及检查更新成功时，通过 result 携带当前应用的完整检测结果，仅查询选中的包并检测指定环境实例，渲染层按 applicationId 替换对应行，并直接更新工具快照中对应的安装信息；不会因任务完成调用 getApplications 或全量工具快照。安装、更新和卸载使用任务开始时确定的环境核对结果，成功或失败均只清除并重新检测此应用的安装缓存，保留其他应用缓存。安装或卸载成功后，主进程保存该实例映射的供应商入口显示偏好，并通过 sidebarVisible 返回所变更的值，界面只合并这一入口；更新或失败不自动修改显示偏好，未接入供应商页面的工具不产生此变更。

检查更新失败时仅清除对应行的最新版本及可更新状态；安装类任务失败时仍呈现重新确认的实际安装状态。成功但缺少结果字段时提示完整重启，以兼容开发中尚未重启的旧主进程，避免误报 npm 查询失败；安装类任务没有结果时将此行标为待确认并禁用安装变更。若与用户主动全量刷新重叠，则在单行检测事件和最终响应中合并刷新过程中完成的任务结果，避免迟到的数据覆盖安装或卸载后的状态。shell 变更立即启动新批次，已确认的行可分别恢复操作。刷新失败停止未返回行的转圈并显示可重试原因，已确认的行保留操作能力。

最新版本通过 Electron net.fetch 直接读取 npm 官方 registry 的固定包 latest 端点，使用系统网络和代理，与 WSL 的安装网络分别处理。进入应用页或刷新时并行获取，同一包只合并进行中的请求，不使用过期版本作为可更新依据；网络失败单独返回版本查询原因，不覆盖安装状态。`application-version.ts` 按 SemVer 比较，支持预发布和构建元数据，数字字段不作字符串字典序比较。只有确认官方版本更高时返回 updateAvailable；更新任务还会重新读取安装版本及官方 latest，避免重复安装或降级，实际 npm 更新使用确认的具体版本。

`application-command.ts` 执行本机命令，Windows npm.cmd 使用经过校验、逐参数引用的 cmd 调用；POSIX 创建独立进程组。后台任务返回状态、有限的步骤记录和完成事件，不返回 npm 原始 stdout/stderr。安装失败按网络、权限、Node.js 版本、空间等分类处理。任务有超时和输出上限，本机按进程树终止，WSL 安装命令由 timeout 管理进程组；运行中的任务阻止正常退出，允许最小化和收进托盘。安装、更新或卸载的最终检测和显示偏好保存完成后才发布终态事件并释放环境写锁；检查结束仅释放对应应用的检查登记。

在此协调目录解析、共通配置、完整预览、切换、备份、原子写入和恢复。路径设置保存配置目录，并兼容旧版文件路径。共通模板按基础工具保存在 SQLite 的 TEXT 列中，保留 JSON/TOML 原文；`managed-state.ts` 按环境记录模型选项接管前值、应用值、所选预设签名、上次应用的共通模板及署名恢复状态。应用供应商时，工具文件、共享模板、接管状态按组备份，写前检测外部修改，由 `database/configuration-targets.ts` 登记待恢复操作、原子替换工具文件、读回校验后事务提交接管状态；失败回滚，启动时恢复中断操作。旧备份缺少状态时清除较新的状态，不回退整个供应商库。

供应商和共通模板按基础工具共用：切换、草稿预览、当前状态匹配和共通字段迁移均通过 `baseToolId` 读取同一份供应商模型、Header、路由及连接能力。目标路径、适配器和接管状态使用完整工具标识；应用到本机或 WSL 仅更新所选环境。保存供应商只更新共用库；保存共通配置只校验、备份并更新应用内模板，不访问目标工具文件，不要求工具或 WSL 可用。共通模板使用独立的 `template` 备份类型，恢复也仅更新应用内模板。云端恢复兼容旧 WSL 供应商和模板记录。

`common-config.ts` 将本机与 WSL 映射到同一条基础工具模板记录，显式空内容也是最终值。启动升级迁移由 [`../migrations/`](../migrations/README.md) 的有序步骤负责，通过 SQLite `user_version` 跳过已完成步骤；旧 JSON 校验、备份后直接导入，不再生成新活动 JSON。旧操作备份先校验原始正文，再映射为数据库模板或接管状态引用。

`configuration-fields.ts` 处理用户主动执行的归属字段移动，不参与启动升级迁移：将共通模板中的连接或模型字段移入明确指定的供应商与预设，写前备份，失败回滚；Claude 仅迁移 Header 和路由，Fast 和自动压缩按未管理字段保留；Codex 迁移模型选项。两个工具的主思考强度都保留为共通顶层字段。迁移只访问应用内供应商和共享模板，不读取或应用工具文件、不广播至其他供应商。Codex 的 API Key、地址和模型只写 `config.toml`。预览在主进程脱敏 Key 和任意命名的 Header 值后返回，不写文件。

`config-preview.ts` 对 API Key、Claude 的 `ANTHROPIC_AUTH_TOKEN` 和 Codex 的 `experimental_bearer_token` 复用供应商摘要的前后缀脱敏规则；其他令牌、密码和 Header 值保持完全隐藏。已知密钥在其他字符串中的副本也会脱敏，采用单次匹配替换，避免再次处理已生成的脱敏内容。

旧版多文件备份先完成正文完整性校验，再仅选取工具配置及当前应用对应的共通模板进行恢复，不读取或写入其他历史关联文件。旧 TOML 未包含密钥时提示重新应用已保存的供应商。

S3 云端备份按方向整份覆盖：上传供应商（含 Key/Header）与两份通用模板到固定 `backup.json.enc`，服务端最后成功提交者生效；应用所选当前/历史存档时覆盖本地供应商和模板，不合并。当前供应商通过工具文件读取匹配，路径设置、主题、接管状态和密码只留本机，恢复不写真实工具文件。完整文件继续用 scrypt + AES-256-GCM 加密，取消新存档格式版本字段与文件名后缀，兼容旧加密文档，忽略旧接管状态。历史独立模板以本机项为准（含 null），不合并。

`configuration-archives.ts` 保存带校验和的覆盖前快照，备份页面可主动恢复；恢复前再备份，正文先写入独立文件并校验，再在同一个 SQLite 事务中登记索引和替换供应商、模板；失败整组回滚。云端上传从短的数据库读事务取得一致快照，不直接上传运行中的数据库。控制器操作锁串行化供应商、模板及恢复，避免应用途中编辑。云端提供存档列表，成功保存后保留带时间戳和 UUID 的历史副本，按用户设定清理；当前对象单独保存。响应丢失时查询本次标识核实提交结果，历史副本或清理失败不会将已成功保存报为失败。

多文件写入需要失败恢复；开发时使用临时目录，只有用户发起应用供应商或恢复工具备份才修改真实工具配置。保存和恢复共通模板只修改应用数据目录。

`wsl-runtime.ts` 统一封装 wsl.exe、账户信息、shell 初始化、白名单环境变量读取与命令执行，不依赖工具标识或包管理器。账户与发行版发现使用独立的 /bin/sh，不依赖用户启动文件；getent passwd（或 /etc/passwd）提供默认登录 shell，/etc/os-release 提供发行版展示名称。随后在 Linux HOME 中统一用 -lic 启动所选 shell，不接受可配置 flag。固定脚本放在继承环境的内层 POSIX shell 执行，以兼容 fish 语法。PATH 解析支持可执行文件与 shim，不补写固定安装目录，不加载特定包管理器脚本，排除继承的 Windows 启动文件。参数独立传入并转义，输出使用 NUL 标记区分启动噪声和命令数据；未找到命令、执行失败和超时分别反馈。

`wsl.ts` 负责工具配置目录映射、环境缓存与版本读取，不处理底层命令执行。npm、原生安装及版本管理器只要在用户 PATH 中提供可执行文件即可共用同一流程；alias / function 和未加入 PATH 的安装不自动识别。WSL 不可用时按入口反馈，不阻断本机状态。WSL 路径只接受 wsl.localhost / wsl$ 共享，四个入口分别持久化工具状态和备份，共用两份模板；恢复工具配置使用备份原路径，写前确认原发行版可用。首次写入可创建缺失的 WSL 目录，所有读操作均不创建文件。

`tool-diagnostics.ts` 按工具目录中的规则解析 CLI 的 --version 输出，Claude Code、Codex 的本机实例兼容 doctor 报告回退。只返回安装版本，忽略 doctor 的认证、网络等健康检查结果；完整报告不经 IPC 返回、不写入日志，不运行自动修复。供应商配置路径及 doctor 特有格式仍独立处理，不影响新增仅管理安装的工具。
